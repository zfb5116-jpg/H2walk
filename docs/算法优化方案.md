# H2walk 算法优化与兼容性说明

核验日期：2026-10-22。第一轮感知优化基线：`06c2617dfea65596fa034806a18bf2e475bf80be`。第二轮已核对上游 `c6b0107`；当前步态问题、奖励修改和实验开关见 [步态诊断与优化](步态诊断与优化.md)。下文保留感知方案与兼容性依据，本轮不使用重建归档。

第三轮进一步修复命令课程，改为按实际前后进度扩速，具体见 [命令课程优化](命令课程优化.md)。感知和观测接口不因此改变。

本版整合已有本地修改与最新 H2 源码。没有启动训练、仿真或真机控制，也没有调用优化器更新。以下收益是研究假设，CPU 合成输入测试不能证明通过率或稳定性已经提升。

## 1. 最新代码与研究边界

最新默认分支已经加入 H2 楼梯任务、LiDAR 观测回调和真实 U-Net。因此，先前快照“尚无 H2 接线、缺少 U-Net”的结论已不适用于本版：

- Rough 和当前 Stairs/Play 默认使用 GT 高度扫描；仅构造配置时显式设 `use_lidar_reconstruction=True` 才为 actor 接入冻结重建器，critic 继续使用 GT。本轮未启用重建。
- 归档模型仍来自 Go2 四足实验。把 12 个 H2 腿关节填入 Go2 输入槽不等于完成了跨机型适配。
- 重建依赖当前仿真中的传感器与机器人位姿。真实部署仍需里程计、运动学、外参和时间同步，不能只因去掉真值速度输入就声称完全消除了仿真特权。
- 本分支保留上游 `logs/rsl_rl/stairs_l0b2_20261020` 实验源码、说明与权重原样，优化实现位于 H2 的 `source/.../h2_task/` 路径。

PIM、SOLO 和 FootQuery 中的 detach 均与独立监督或优化路径配套；detach 本身并非错误。这里的问题是已配置 PPO 路径未提供相应辅助更新，因此默认使三组编码器作为任务潜变量获得 PPO 梯度，显式冻结仍可选择。

本版可研究的问题是：**在相近整体高度误差下，可靠性约束与台阶边缘保留是否能降低下台阶的落脚失败？** 可靠性、门控和历史检索已有研究先例；组合这些机制不自动构成科研创新。

## 3. 算法实现

### 3.1 动态观测布局与梯度通路

`networks/actor_critic_our.py` 根据动作数计算 term-major 历史切片：

`actor_dim = 3 + history_length * (6 + 3 * num_actions) + height_scan_dim`

29 动作、5 帧历史和 561 个高度点对应 1029 维，扫描起点为 468。原网络硬编码 28 关节和“至少 1014 维”检查，可能让错位继续运行。现在 actor/critic 分别严格校验宽度，支持显式 28 动作与自定义历史/地图大小。

默认 `detach_estimates=False`；改为 True 只在调用方提供独立辅助训练路径时使用。编码器名称延续旧键，但其输出没有物理量准确性保证。

### 3.2 可靠性约束融合

H2 的 `networks/terrain_fusion.py` 和 `lidar_terrain_reconstructor.py` 提供可选 `use_reliable_fusion=True`：

1. 使用原有历史位姿重投影，不重复发明运动补偿；当前帧只计一次，部分环境 reset 后旧帧不参与。
2. 几何高度仍取有效帧中位数。按有效支持、帧龄、跨帧 MAD 加平均绝对离散度和格内上下层跨度估计可靠性。
3. 在几何高度与空洞初值周围允许 `(1-c) * residual_limit_m` 的总修正；refine、edge clean 和后处理后仍投影回相同边界。
4. 对高可靠或窄几何结构使用同踏面中值；仅低可靠孤立点可在足够可靠且一致的邻域支持下被修正。

可靠性是启发式分数，不是校准概率或测量方差。它没有新增 learned 参数或持久 buffer，legacy/robust 的 state_dict 键与形状一致，但启用后输出分布可能改变。

对于 3×3 邻域，只有中心可靠性低于 0.25，且至少 5/8 个可靠性不低于 0.5 的邻点在门限内一致，才使用邻域值修正孤立点。低可信的真实窄踏面也可能满足此规则而被移除，必须用真实回放评价这项取舍。

默认尺度为：跨帧离散度 1 cm、层间跨度 1.5 cm、年龄衰减 50 个控制步、总残差 8 cm、同踏面高度门限 1 cm。单个内部一致的新观测可靠性为 0.5。当前仍会舍弃部分被 mixed-pixel 过滤或 upper-band 选取去掉的层次；算法不能从不存在的证据恢复真实台阶。

### 3.3 修复真实 H2 观测接口

`mdp/observations.py` 与纯 torch 的 `networks/lidar_observation.py` 负责：

- 从传感器 pattern 读取最小距离；不再访问不存在的 `model.min_range`。
- 无效/缺失回波保持 mask=0，不把它们投到世界 z=0 平面并伪装成有效地面。
- 检查射线数量、方向、统一起点和 checkpoint 元数据；不静默解释不匹配的球面网格。
- 默认使用明确的零速度先验，而不是把仿真真实线速度填入 Go2 估计速度槽。可选择外部估计接口，缺失或形状错误时拒绝继续。
- 在相同状态/step 重复读取时复用结果；reset 清除相关缓存、隐藏状态和历史，位姿变化不会直接返回旧地图。

默认输出与 Isaac Lab `height_scan` 对齐。重建器给出 `h_body = terrain_z - root_z`，转换为：

`height_scan = reference_sensor_z - root_z - h_body - offset`

其中 offset 默认 0.5 m，reference 使用原 height_scanner 的附着 pose；这里只读其位置，不读取 GT ray hit。随后 ObservationManager 沿用 clip[-1,1] 和 scale=0.2。网格维持 ny×nx 行优先，默认 GridPattern ordering='xy' 与其一致，无需转置。

依据：[Isaac Lab height_scan](https://raw.githubusercontent.com/isaac-sim/IsaacLab/v2.1.0/source/isaaclab/isaaclab/envs/mdp/observations.py)、[网格 ordering](https://raw.githubusercontent.com/isaac-sim/IsaacLab/v2.1.0/source/isaaclab/isaaclab/sensors/ray_caster/patterns/patterns_cfg.py)。仓库未固定 Isaac Lab 版本，实际环境若采用不同语义必须重新核对。

## 4. 开关与 checkpoint 兼容性

重建和可靠性分支默认关闭。只有明确需要感知实验时，在构造配置时一并启用：

```python
cfg = RobotStairsEnvCfg(use_lidar_reconstruction=True,
                       lidar_reliable_fusion=True)
```

该示例只是配置构造，不启动环境，本轮没有执行。仅改 `lidar_reliable_fusion` 不启用重建；构造后只修改布尔字段不会自动重配传感器和观测。

观测参数包括 `output_convention="height_scan"`、`height_scan_offset=0.5`、`reference_sensor_cfg`、`velocity_source="zero"`。要供给部署可得速度，使用 `velocity_source="estimate"` 并提供约定的机体系估计缓冲区。零先验是有意选择的消融条件，不是准确速度估计；它与 Go2 训练时的估计速度分布不同。旧 body-height 语义仅可作为显式对照，不能与 height_scan 归一化器混用。

必须区分三种兼容性：

- **参数兼容**：可靠性开关不改变重建器 state_dict。
- **布局兼容**：28→29 动作改变多个权重形状，不能静默迁移旧 actor。
- **行为兼容**：地图符号/偏移修正、miss 处理与速度先验均会改变观测分布。旧经验归一化器和策略需要单独验证，不能因严格载入成功就宣称可直接恢复训练或部署。

不使用 `strict=False` 掩盖 checkpoint 不匹配。本次没有读取或下载训练权重；CPU 检查使用随机初始化参数。

## 5. 离线评价与后续实验

`tools/terrain_metrics.py` 接受 NPZ 的 `prediction`、`target`，可选 `observed` 和 `confidence`，形状为 (H,W) 或 (B,H,W)，单位米。报告 MAE、95% 分位误差、梯度误差、边缘 F1、方向准确率和有回波/空洞分区误差。

```shell
python tools/terrain_metrics.py path/to/maps.npz --output path/to/report.json
```

默认边缘阈值 1.5 cm，严格匹配格间边界，无空间容差；无边缘或空分区返回 null。可靠性分桶只报告误差，不声称完成概率校准。没有实际回放数据时，不生成假装来自机器人的性能报告。

后续授权训练时建议等预算比较：legacy；只换滤波；只加可靠性；两者组合；最后比较 GT teacher 与感知 student。固定独立地形划分，至少三个随机种子，分开报告上下台阶、低/高台阶、转弯、遮挡、掉帧和位姿偏差。最终关注路线通过率、每米跌倒次数、速度跟踪与端到端延迟，而不是只看训练 snapshot 的平均高度误差。
