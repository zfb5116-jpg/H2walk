## 真实结果说明什么

[上一轮完整诊断](20261028训练失败诊断.md)已将新增三段 event 与 source12ee 对齐至实际 29999 零基 iteration，不能沿用早期 HF README 的旧配置。末段回合均长约 4.45 s，`base_contact` logger 均值约 .989；该聚合量不是独立重建的逐回合跌倒概率，更不区分骨盆撞地与自碰。命令课程有运行证据，但没有成功扩速；因此没有证据归因于“扩速后崩溃”。RND 末段 intrinsic/extrinsic 约 2.72%，不能按旧 YAML 的 weight=25 直接指认它主导失败。

## 奖励仍可能把学习引向哪里

以下均为实际生产函数的 CPU 数学反例，不能证明旧 run 已访问该状态或采取该行为。

| 项目 | 已复现性质 | 对学习的含义 |
| --- | --- | --- |
| XY 与名为 progress 的 forward 项 | 命令 .2 m/s，静止 `[0,0]` 与速度 `[0,.4]` 的加权 tracking 均值同为约 2.2677；平稳 `[.2,.2]` 为 10 | 瞬时核能奖励准确跟踪，却不能为这两种净推进不同的轨迹提供区别；再加动作成本，脉动步态可能吃亏。不是相对核独有的问题，也不是所有行走都劣于静止 |
| air/contact 事件项 | `-abs(last_duration-.45)*first_event`，最多为零；不发生事件时为零 | 它们是固定时长偏差损失，没有正向交替迈步奖励；注释已更正，公式仍保留作对照 |
| air/contact 时长差平方 | 一脚首次支撑 19 s 后起步，旧 variance 合计为 45.1875 | 迟来的首次抬脚可能遭遇异常放大的成本。本轮仅为新 Walk 提供有界差值模式，详见下文 |
| terrain swing 高度 | 不接触的单脚静态保持在平地上方 3 cm，实际 vx=0、命令 .2，仍可获得该项满分，即当前权重下 +.75/时间单位 | 这项没有水平移动、有效推进或交替条件；局部得分不等于完整动力学下悬停必是最优 |
| nearest 楼梯高度 | 实际 561 点网格上，未落地的脚前移 6 cm，目标可从第一阶上方跳到第二阶上方；原高度得分从 1 降至约 .00193 | 当前是逐帧几何查询，没有一个摆动周期内的落脚目标锁存或连续轨迹；净空修复没有解决这个问题 |
| 基座高度 | `-min(feet_pos_b.z)` 是身体轴到较低 ankle link 的距离 | 属于腿伸展/姿态先验；全身平移离地时可能不变，不能把低损失叫作骨盆离地高度正常 |

阶段 evaluator 读取有符号实际推进与支撑证据，**只作阶段验收，不给 PPO 增加进度奖励**。不能因为验收使用了真实位移，就宣称优化目标也已解决静止/往复问题。新增时间边界同样没有解决表内其余风险。

## 真值与动作设置

核对 [Isaac Lab v2.2.1 height_scan](https://github.com/isaac-sim/IsaacLab/blob/v2.2.1/source/isaaclab/isaaclab/envs/mdp/observations.py) 后，扫描采用 sensor 世界 Z 减命中世界 Z 再减 .5 偏置。20 m 是 ray-start offset，未发现整张观测被错误抬高 20 m 的问题。17×33 共 561 点与查询坐标可对齐，当前 actor 不按另一个网格顺序 reshape。

但输入 clip 会损失远处下楼信息：骨盆 Z=1.03 m 时，下降 .6 m 与 .8 m 的 actor 扫描都饱和为 .2；下降 .2/.4 m 仍可区分，不能说全部扫描失效。准确几何也不等于足底覆盖、压力分布、摩擦裕量或可达落脚点。新 filtered ground 正 Z 力和 sole/GT 容差只是支撑证据，尚未通过 PhysX 后端验证。

历史编码器名称含 velocity/contact/prediction，但目前没有对应物理量的独立监督，属于 PPO 任务潜变量，不能当作已经准确的物理估计器。actor 的部分可观测性与固定缩放后的实际特征分布仍待运行数据检验。

[Unitree 官方 H2 固定版本](https://github.com/unitreerobotics/unitree_rl_mjlab/blob/1425b15f73bd4095f0df53709d7c389c3eb9e790/src/tasks/velocity/config/h2/env_cfgs.py)采用按 effort/stiffness 分组的动作尺度。本项目仍为全关节 .25。以默认位姿、raw action 独立零均值单位 Gaussian 作纯静态计算，踝 roll 目标超 soft-limit 概率约 24.77%，官方 .11875 尺度约 1.68%。这是目标分布推算，不是实测关节超限率；官方膝部尺度更大，该处理论超限率也更高，不能据此照搬整套参数。PD 增益、动作探索与力矩/关节限制需要联合看实际分位数。

## 论文与 main 对照

阅读原文后，下列方向有依据，但没有一篇论文证明本项目现有参数必然能训练成功：

- [FastStair v1](https://arxiv.org/html/2601.10365v1)以规划落点及连续摆脚轨迹指导分阶段训练，支持把稳定支撑、落点和摆动时序作为独立问题；不意味着必须引入其 DCM/LoRA。
- [Gait-Adaptive v1](https://arxiv.org/html/2512.07464v1)将关节动作与有界平滑步频共同学习，并维护两腿相位。它支持重新审视固定 .45 s 时长偏好，但其 31 DOF Oli 平台不能直接证明 H2 参数合理。
- [RPL v1](https://arxiv.org/html/2602.03002v1)的足底覆盖/边缘约束，以及 [Hiking in the Wild v1](https://arxiv.org/html/2601.07718v1)的脚体积/地形边缘与可行区域，说明“有 GT 高度和净空奖励”仍不足以保证有效落足。
- [Unitree 公共 velocity 配置](https://github.com/unitreerobotics/unitree_rl_mjlab/blob/1425b15f73bd4095f0df53709d7c389c3eb9e790/src/tasks/velocity/velocity_env_cfg.py)有显式 gait 和 termination 项。不同后端与奖励组合不能直接移植权重，尤其不能仅搬入一个大失败惩罚便声称解决稳定性。

main 新提交已去除上肢锁定/重建侧边噪声、默认 GT，并增加独立 Stairs experiment name，这些方向与本分支既有实现相符。其新 `forward_progress` 对正向速度取正值再按目标饱和：命令 .2 时，`[+.4,-.4]` 净推进为零，该单项均值仍为 .5。它不是真实有符号净推进，本轮不直接搬入。若后续新增位移塑形，需要验证时间尺度、饱和、方向与 reset 语义；仅改名 signed 也不构成证明。

main 的 Train X=.15–.35/初始 level0，Play X=.20–.45/初始 level5，条件不同；同一权重也不能直接凭录像比较。固定 body-Z 脚高 -.83 仍是几何先验，本分支保留 terrain 净空。此次不整体合并 main，不改变 main，也不覆盖他人提交。

## 本轮落实的边界修复

### 时序异常放大

`air_time_variance_penalty` 的两个方差原先只对时长 clip 到 .5 s，cross 项未限制。本轮 base 函数缺省 `cross_time_mode="legacy"` 保留旧任务；新 Walk 缺省 `walking_cross_time_mode="bounded"`、`walking_max_time_difference=.5`，计算：

```text
cross = .25 * mean(clamp(last_air-last_contact, -.5, .5)^2)
```

因此 cross 单项上限 .0625；两个方差仍需另外相加。上述单脚 19 s 反例的总值由 45.1875 降为 .09375，不能把总上限写成 .0625。截断差值保留两个长时长之间的小差异，不是分别 clip 两个时长。该边界是可解释的实验设置，尚未验证最优步频。新 profile 构造时可显式选 legacy 作对照；构造后仅改 flag 而未改实际 params 会被拒绝。

### 实际入口与 checkpoint 协议

用户 HF 归档使用过的 `tools/train.py` 只接受旧 Flat/Rough/Stairs 三种 ID。继续用旧默认命令不会进入新 Walk；新增注册本身没有解决这条操作路径。本轮提供仓库内 `tools/train_walk.py`，缺省 Bootstrap，明确支持六个阶段，通过 registry 同时解析环境与 runner。模块导入、纯 parser 与 `--help` 不启动 Isaac。

受审入口固定 RSL-RL 2.3.3；记录实际 task、source Git SHA/dirty/内容 hash、阶段、输入协议与真实运行时维度。`--max_iterations` 是本次追加请求，完成次数来自 checkpoint/运行状态，不从参数推定。未指定 checkpoint 即新运行；不自动搜寻 latest。

旧 normalized checkpoint 与新 fixed-scale 权重同形，但[官方 RSL v2.3.3 loader](https://github.com/leggedrobotics/rsl_rl/blob/v2.3.3/rsl_rl/runners/on_policy_runner.py)会在新 runner normalization=False 时跳过旧 normalizer。CPU 控制流已复现静默忽略的可能；**不是旧 source12ee run 已犯此错的证据**。

新入口的每次自动保存都附带 producer marker；恢复前验证固定布局/实际观测与动作配置指纹、normalization=False、RND=None、时序模式和边界、iteration 记录。只读取一次 `weights_only=True`，检查通过后才应用模型/优化器状态，不再调用官方 unsafe loader 二次读取。相同协议允许阶段迁移，来源 hash 与阶段会记录；这不构成模型质量或来源真实性的密码学保证。

旧/未知 marker、旧 normalizer/RND、同维度但改缩放/顺序的配置都会被拒绝。此前 abed 的无 marker fixed-scale 权重也不会自动当作兼容，需要另核来源并设计显式迁移；不提供丢弃统计的隐式绕过。网络 tensor keys/形状没有改变，环境统计窗口仍不随 checkpoint 恢复。

**保护限于这个受审入口。**外部标准 train/play loader 仍可能绕过它；不能将它们称为同样受保护。旧权重诊断继续使用原配套归一化/runner 和基线任务。新权重播放同样需要保持固定缩放协议及匹配配置，不能凭维度相同直接换 loader。

## 对下一次训练的合理预期

本轮使异常幅值和协议误用更可控；分阶段保留扫描和平地回归也比直接在复杂楼梯上无法区分故障更易诊断。仍不能预测收敛或承诺正常行走。固定 .2 m/s、零转向、默认无扰动的六档只覆盖基础能力，即使全部达标，也没有覆盖最终 rough/slope、变速、转向和扰动恢复。

后续获准动态实验时，首先区分物理支撑/自碰问题与奖励目标问题；以同 checkpoint、同命令、同地形和同输入统计验证完整回合生存及有符号推进，再单独验证交替步态与楼梯目标锁存/落足质量。若基础仍失败，应优先检验步态/进度信号和按关节探索尺度，而不是默认增加训练轮数或扩大网络。详细 CPU 数量、独立审查与发布边界见[验证记录](验证记录.md)。
