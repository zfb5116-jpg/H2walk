# 2026-10-28 新训练结果：失败证据与下一版调整边界

本次目标是普通地形稳定行走，并逐级达到上下楼。结论是：**这次训练仍未建立足够的基础稳定性，不能认为已经学会普通地形行走、只差适应高楼梯。需要调整训练流程、接触诊断和验收，但现有证据不足以判定必须替换 PPO 或扩大网络。**

本报告分析的是 10 月 27–28 日的新 run，不是此前 10 月 23 日的旧 30k run。此前 796 项 CPU 测试和 14 项子测试检查代码性质，没有证明实际步态收益；新日志已经表明，不能据此预测该配置训练后会成功行走。

这里的“尚未修改/发布算法”描述的是 2026-10-28 诊断结束时的状态。2026-10-29 后续实现见[接触诊断与分阶段行走](接触诊断与分阶段行走.md)；诊断中的未验证步态结论仍然成立。

本轮只做源码、原始 TensorBoard、视频抽帧、静态 USD 几何和 CPU 合成反例核查。没有启动训练、仿真、真机或策略，没有调用 `optimizer.step`，没有反序列化 `.pkl` 或加载 checkpoint。

## 3. 第一优先级：骨盆接触终止的来源

本次 `base_contact` 配置只选择 `pelvis`，历史净接触力范数大于 **1 N** 即终止。ContactSensor 未配置接触另一方过滤，资产启用了 self collision。[Isaac Lab v2.2.1 illegal_contact](https://github.com/isaac-sim/IsaacLab/blob/v2.2.1/source/isaaclab/isaaclab/envs/mdp/terminations.py) 只检查该力张量；[ContactSensorData](https://github.com/isaac-sim/IsaacLab/blob/v2.2.1/source/isaaclab/isaaclab/sensors/contact_sensor/contact_sensor_data.py) 将净法向力与按另一方过滤的 force matrix 区分。当前日志没有碰撞对身份。

CPU 反例中，给骨盆相同的 1.01 N 净接触力，假设它来自地面或者自身其他 link，终止函数都会返回 True。这个反例证明现有 predicate 无法区分来源，不证明本次真的发生了 self collision。姿态终止少，也不等于身体没有塌低触地。

静态 USD 核查发现 23 个碰撞体，骨盆为 convex hull，自身碰撞启用，未找到显式 filteredPairs。直接关节相邻 link 的碰撞关闭，但骨盆与 hip-roll 并非直接关节邻居。按配置站姿进行纯 CPU 正运动学，零角姿态与 USD 变换最大误差约 `1.66e-7`；骨盆与两侧 hip-roll 球体包围盒相交。凸几何探针未取得严格交叠的阳性结果，但其失败结果没有保存求解状态，不能区分不可行与数值失败。**这些证据不能证明存在或排除初始站姿穿透。**动作后的碰撞、实际 PhysX cooked hull 与接触仍未检查。静态几何不能代替动力学接触记录。

下一版必须区分这些可证伪方向：

1. 骨盆确实触地：终止前应同时观察到骨盆离局部地面的高度降低、关节塌低和相应地面接触力。
2. 骨盆与腿或上身自碰：骨盆仍高于地面时，应出现 robot-link 接触对；不能只看净力推断。
3. 接触映射、资产或数值设置异常：需核对运行时 sensor body 名称、索引、实际资产哈希、接触另一方及发生时刻，不能靠提高阈值把问题隐藏。

应在 reset **之前**记录：地形列/行、env ID、终止项共同触发、pelvis 高度/倾角、地面与自身接触对/力、关节位置/速度/力矩、逐脚支撑/滑移、raw 与 processed action。净力历史已有信息不能凭空还原接触另一方；需要独立过滤的诊断通道或实际 contact-pair 接口。

[Unitree 官方 H2 配置固定版本](https://github.com/unitreerobotics/unitree_rl_mjlab/blob/1425b15f73bd4095f0df53709d7c389c3eb9e790/src/tasks/velocity/config/h2/env_cfgs.py#L39-L59) 分别配置 feet-ground 与 self-collision 通道，支持这里先区分接触来源的诊断设计；它不能证明迁移其配置就能解决本项目问题。也不能直接关闭 self collision、去掉骨盆终止或放宽阈值，以“存活变长”替代行走改善。

## 4. 其他解释的证据强弱

**控制链。** 三份归档的动作与关节观测都按 `H2_JOINT_NAMES` 且 `preserve_order=True`；处理目标为 `default_joint_pos + .25×raw_action`，29 维一致。动作历史和该仿射目标的 CPU 反例检查通过。未发现确定的关节错序或动作缩放断路。PD、力矩/延迟、solver 迭代及真实足底支持是否适合 H2，仍需要运行状态，静态检查不能证明它们没有问题。

**RND。** event 中 weight 始终为 .5，非 YAML 表面值 25；loss 与非零内奖励表明该支路参与运行。末 1000 的外奖励均值 11.65166，内奖励 .317196，均值比为 **2.7223%**。首 200 的外奖为负，内奖约为外奖绝对值均值的 .94%；正负抵消时不能使用简单 I/E 作为“占比”。这些数据不支持把 RND 奖励主导当作已证原因，仍不能替代关闭 RND 的因果消融。

**楼梯奖励。** 末 1000 的 `feet_stair_clearance` 日志均值约 `1.38e-6`，`feet_swing_height` 约 `.00220`，显示收到的楼梯塑形信号很少。每个奖励项按配置最大回合秒数归一，不能与 Train/RND 的回合总回报直接比大小。新 run 没有逐脚门控开启率、实际目标高度、摆动中换靶、脚地接触对或支撑覆盖，因此不能区分“没有走到台阶”“未进入有效摆动”和“门控/目标不适配”。nearest 仍是反应式抬脚奖励，不是落足规划器，不处理下楼目标，也没有解决支撑覆盖。现在继续单独加大其权重没有证据依据。

**速度指标。** 末段 `error_vel_xy≈.0208` 不能写成实际均速误差只有 .0208 m/s。[官方 UniformVelocityCommand](https://github.com/isaac-sim/IsaacLab/blob/v2.2.1/source/isaaclab/isaaclab/envs/mdp/commands/velocity_command.py#L111-L121) 每步按命令重采样上限归一累加；本次上限为 12 s，短回合会压低累积日志。CPU 反例中，同为 .2 m/s 恒定实际误差，.8 s 回合记为 .01333，4.46 s 记为 .07433；仅因回合缩短，累计日志就会变小。应另记按真实暴露时间归一的误差、速度轨迹和有符号净进度。

**训练量。** 新 run 是 1024 环境，30k×24×1024=737,280,000 个环境步；旧 run 是 4096 环境，同迭代数对应四倍采样量。不能把二者称作同等训练预算，也不能据此认定“再多训四倍就能走”。新旧源码、奖励和环境分布也不同，不能将旧长回合与新短回合差异全部归因于某一项改动。

**视频。** 新附件长 12.5 s，1280×720、30 fps、375 帧；两窗口中可见低位失稳/小幅迈步，未展示持续跨越多级楼梯。视频 SHA256 为 `f2c2b6951b4f812123c3b6daa74266ac869422a1bc947b46b6189e9304f9cfba`。左右窗口的 checkpoint、task、命令和归一化统计未知，不能指认哪边对应中间/末期、比较优劣或据此宣布后期退化。训练日志自身已足以说明基础稳定性不足，无须先向用户追问播放命令。

## 5. 下一版应改到什么程度

建议进行**训练协议和验收层面的较大调整**，先保留可解释的 PPO 与当前网络作为对照。不能承诺调整后一次训练必然成功；下面是可实施、可回退的实验顺序，不是已训练验证的配方。

| 阶段 | 最小范围 | 进入下一阶段的证据 |
| --- | --- | --- |
| P0 接触诊断 | 保留原终止，补 reset 前状态、地面/自身接触区分、分地形统计 | 明确主要提前终止来源，避免把假接触或真实塌低混为一谈 |
| P1 基础步态 | 新增保留 GT 扫描的 bootstrap profile；固定低速前向命令、先去掉侧向/大角度转向；push、DR、RND 作为分别控制的消融开关 | 同条件平地重复完成 20 s，并有实际前进、真实误差、足支撑与接触证据；仅站住不算通过 |
| P2 浅阶 | 2–5 cm 上/下楼，并持续保留普通地形样本；记录台阶跨越和足底有效支撑 | 上楼和下楼分别达标，普通地形不退化，逐脚净空/支撑有效 |
| P3 难度扩展 | 分档到 8/12/16/20 cm，再逐步恢复转向、扰动与感知变化 | 每档独立评估，按地形报告通过率和失败类型，不能只看总体 reward |

验收阈值应在新实验前固定，例如每类固定 seed/命令/地形与足够重复回合，报告区间；具体门槛属于后续实验设计，不把当前课程的 80% 命令进度率冒充上楼通过率。任务坐标应明确上下楼方向，设置真实跨阶/到达目标的检测，修正径向距离并不等价楼梯完成的问题。

P1 不能直接使用现有 Flat task 作 checkpoint 替换：它删除 height scanner，输入维度和语义不同。bootstrap 应保留 561 扫描及 actor1029/critic866/29动作，旧 mixed 配置作为显式基线保留。若实验限制上肢动作，训练、评估和导出必须使用相同限制，不能训练锁定而播放释放未训练输出。

归一化也要单独设计。[RSL-RL v2.3.3 runner](https://github.com/leggedrobotics/rsl_rl/blob/v2.3.3/rsl_rl/runners/on_policy_runner.py) 的参考实现设置经验归一化 `until=1e8`；若实际依赖一致，纯平地训练足够久后再进入楼梯，统计可能已经冻结。不能静默清空统计，也不能假定 resume 自动适应新地形。本次未读取新 checkpoint 内的 count，实际依赖版本和统计状态仍缺失。每阶段必须保存并记录配套统计及更新/冻结策略；结构维度兼容不等于行为或归一化兼容。

[RPL 原文 v1](https://arxiv.org/html/2602.03002v1) 使用高度图专家与后续蒸馏，并讨论足底覆盖；[Hiking in the Wild 原文 v1](https://arxiv.org/html/2601.07718v1) 将几何危险和可达区域命令一起设计。它们支持先获得稳定能力、再处理可达任务和支撑几何的研究方向，不证明本报告的阶段参数、当前 nearest 或某个权重已经最优。

## 6. 检查结果与剩余限制

已完成：固定 HF 版本的 3 份 source 与 3 份 event 哈希核验；三段训练源码/实际 YAML/恢复索引对照；330 万原始标量点独立复核；108 个迭代标签连续性、有限值检查；静态 USD 与初姿态几何检查；控制/接触/指标的 4 组合成反例；整段曲线导出。曲线使用非重叠 100 迭代块均值展示，表格用原始值，不使用 TensorBoard reservoir 抽样。

本报告与离线脚本通过独立 code-reviewer 审查，脚本另经 Python reviewer 审查。审查中修正了完整性检查依赖 `assert`、几何求解失败被过度解释，以及动作裁剪示例没有真正触及边界的问题；4 组合成反例重跑通过，4 个脚本 AST 通过。lint/type 工具未能运行，不能声称这些检查通过。审查结论只覆盖离线诊断，不是新算法或步态性能通过。

未完成：动态接触对、真实 per-terrain 通过率、checkpoint 张量与归一化状态、依赖精确版本、左右视频条件对应关系、RND 因果消融、策略推理和闭环步态验证。本轮没有因为缺少这些资料就停止源码与 CPU 核查，也没有通过随意放宽终止或加权重来制造改进结论。

本轮保存诊断报告及离线证据，**尚未把上述阶段方案改成生产算法，也未发布新的算法提交**。当前已训练的 `12ee7f17e0ddb4e276b36dedd631413fcfc916e0` 不能被描述为已验证达到普通地形和楼梯目标的版本。
