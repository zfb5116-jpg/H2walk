# main 对照、训练预期与第六轮补强

核查始于2026-10-25，最终核验日期为2026-10-26。优化基线为 `248573394a0ad0147d13fb240340cd1a4ef6c802`；对照 main 固定为 `c4ba81229d077e9dfe7e5623ab8588b10f6fef7f`。本轮仍不启动训练、仿真、真机或优化器更新，不加载保存策略，不反序列化交接 pkl。只在用户算法分支做白名单增量，不修改或合并 main。

## 可以怎样预期训练效果

上一版修正了明确的接口和奖励问题，但还不能据此预测“训练30000轮就能正常上下楼”。已有真实运行证明长存活可以与约15%的有效进度课程成功率并存；这不是行走能力。新版本也没有实际运行结果，不能给成功概率或训练轮数承诺。

本轮的合理预期限定为：恢复低速和饱和 yaw 命令下的楼梯塑形信号，增强近地摆脚与足够净空的区分，保留初期速度误差较大时的宽核回报比较，让20cm目标与筛选上限配套，并限制普通地形成绩掩盖个别楼梯失败后继续扩速。它们是更适合验证的训练条件，不是成功保证。普通地形、上楼和下楼必须分别验收，同一 checkpoint 的混合平均回报不能替代这些结果。

### 速度奖励的可复现冲突

main 新X项只比较 `vx-cmd_x`，只要平面命令非零就开启；新侧向项惩罚 `vy²`。真实函数的CPU反例：命令 `(0,.2,0)` 时，静止拿X项满分且侧向罚0；正确 `vy=.2` 的X得分相同，却额外受罚 `.04`。这不适合当前有非零Y命令的任务。新heading函数实际比较yaw rate，与当前已有官方yaw-rate项等价，不能将函数名解释为额外的heading角跟踪。

### 边缘项为什么暂不启用

main 将561个扫描点固定重排为 `[33,17]`。但配置没有显式修改 [Isaac Lab v2.2.1 GridPatternCfg](https://github.com/isaac-sim/IsaacLab/blob/v2.2.1/source/isaaclab/isaaclab/sensors/ray_caster/patterns/patterns_cfg.py) 的默认 `ordering="xy"`；[官方实现](https://github.com/isaac-sim/IsaacLab/blob/v2.2.1/source/isaaclab/isaaclab/sensors/ray_caster/patterns/patterns.py)对应 `[17,33]` 再展平。错误邻接会把跨行远点当作近邻。

对main真实函数做AST隔离CPU反例：世界完全平地、脚水平移动 `.1 m/s`、身体pitch仅10°时，官方扫描排列产生 `.1017428` 假惩罚，按权重-4约为 `-.40697`；同一物理点按函数预期排列时为0。这不是仿真结果，但足以否定“没有边缘就必然零罚”的数值性质。

此外，main默认体积点明确沿用G1，盒底z=-.04，而已核H2 sole底面z约-.0543，相差14.3mm且左右脚偏置不同。其点速还混用COM线速度与link原点局部偏移；[官方 ArticulationData](https://github.com/isaac-sim/IsaacLab/blob/v2.2.1/source/isaaclab/isaaclab/assets/articulation/articulation_data.py)中这两个参考并不相同。扫描数量不符时静默返回0、无效脚状态可能传播NaN，也需要独立修复。当前分支没有引入这项，因此不能声称本轮已解决接触前几何规划或足底支撑覆盖。

[Hiking in the Wild 原文v1，III-C/III-D](https://arxiv.org/html/2601.07718v1)使用网格邻面边缘与足碰撞体积，并结合可达平坦区域生成命令。main扫描连线近似不是同一构造；其前向相机协议下的零侧速也不能直接搬到任意Y命令任务。本轮保留原文对几何和可达目标的要求，没有宣称复现论文。

## 本轮针对当前分支的改进

### 1. 速度跟踪混合宽、窄两种带宽

上一版 `command_relative` 在低速时带宽最低为 `.05 m/s`。实际float32函数输入 `cmd_x=.1, vx=1.1` 时回报下溢为0，而旧absolute仍为 `.0183156`。这说明远离目标时可丢失行为比较信号，不说明旧训练曾出现该速度，也不是奖励梯度会直接决定PPO梯度。

新增 `command_relative_mixed`：

```text
mixed = (1-alpha) * absolute + alpha * command_relative
alpha = .75
```

XY与forward使用同样定义，权重、正确跟踪满分和原forward门控保持不变。Stairs默认使用混合模式；`absolute`与上一版`command_relative`保留，alpha=0/1分别精确回到两种核。

| cmd_x / 实际vx | absolute | command_relative | mixed(.75) |
| --- | ---: | ---: | ---: |
| .1 / 0 | .960789 | .018316 | .253934 |
| .1 / 1.1 | .018316 | 0（float32） | .004579 |
| .2 / 0 | .852144 | .018316 | .226773 |
| .2 / .1 | .960789 | .367879 | .516107 |
| .2 / .2 | 1 | 1 | 1 |

alpha是可解释初值，未经过训练选择。混合项仍允许静止得分，也仍会改变外奖分布；旧运行RND的1.66%不能外推。日志中的动作std约.65没有速度单位，不能把它当成 `.65 m/s` 速度噪声。

### 2. 低速与转向边界不再关闭全部近阶信号

上一版nearest要求 `cmd_x>.15`、`abs(cmd_y)<.15`、`abs(cmd_yaw)<.3`。heading控制正好会把yaw命令clip到±.3。相同8cm台阶和正确sole高度的CPU反例，yaw=.2999时得分.5，yaw=±.3时为0。

新对齐模式在 `cmd_x>=.1`、`abs(cmd_y)<=.15`、`abs(cmd_yaw)<=.3` 时允许nearest信号；仍限制强转向、侧移和倒走。共享swing移动门控同样覆盖 `.1 m/s` 进度统计起点。旧strict门控可恢复。

### 3. 最低净空有可辨识的奖励差

3cm最低净空配10cm带宽时，卸载脚0cm净空得 `.913931`，1cm得 `.960789`，3cm得1；近地拖行与充分离地的得分区分较弱。新terrain对齐模式使用3cm带宽，0cm得 `.367879`，3cm及以上仍为1。旧10cm带宽与body_legacy原式保留。接触门控仍存在，不能将卸载脚反例解释为支撑脚站立能拿满分。

### 4. 20cm范围与目标上限配套

`progressive_20cm` 仅在已复制的generator上把两类high上/下阶范围改为 `(.08,.20)`；浅阶、普通地形、6行难度和Play初始level3保留。nearest最大可接受抬升同步改为 `.24`，避免扩几何后16cm以上反而失去目标。独立rise权重尺度仍用 `.16`，不因放宽可接受上限而稀释原2cm低阶信号。

`legacy_14cm`恢复上一版几何和筛选。high范围扩大也会使其首行随机采样上端略增（约9cm到10cm），不能称所有初始tile逐值不变。行内随机难度不保证最后一行每块地形正好20cm；这不是已通过20cm，更不是新下楼规划器。nearest依然只针对前向抬升，下楼依赖共享运动目标与未来需要验证的落脚稳定性。

### 5. 各固定地形列分别通过才扩速

真实课程类的100个合成回合反例：50个普通地形全部通过、50个楼梯中30个通过，总体恰为80%可扩速；一类占10%的楼梯完全失败、其他都通过，总体仍90%。不能夸大成“全部楼梯失败也能扩速”，那时总体只有50%。旧event实际没有扩速，这个问题是新混合分布的目标保证缺口。

Stairs训练默认 `walking_command_curriculum_mode="terrain_columns"`。固定列生成器下，每列至少32个当前generation候选且成功率至少80%，同时满足原全局门槛才扩速；不从当前reset小批次推断缺失的列。某列样本不足时继续累计，不能周期性清空使稀少列永远攒不到样本。列类型在该生成方式中固定，地形课程只改难度行。

全局模式 `global` 保留，Rough/Flat保持原默认；Play保持global，不将随机tile列号作为地形家族。训练使用列模式时，随机tile生成或未覆盖预期列会明确报错；特别小的debug环境应显式改global。64环境收齐32例/列会比4096环境更慢，可能更长时间不扩速；门槛未通过新训练校准。分列命令进度达标仍不等于完成楼梯穿越，地形升行的径向位移判据也未替换。

独立审查发现，仅检查分组张量identity不能阻止原地交换合法列号。最终核心保存独立clone快照，首次没有候选时也固定映射；后续内容一致性并入既有紧凑validity汇总，在消费新reset证据前拒绝变化，异常时reported、计数和last-step均不更新。该保护不表示官方Importer会改变列分配，也不是旧训练失败证据；GPU性能仍未实测。

课程日志增加active进度、inactive残差、目标距离的分解及各列样本/成功率，并固定各reset的日志键，避免只在少数评估reset新增键而被runner漏掉。首次评估前用 `has_evaluation=0` 标识，不把零初值当真实失败窗口；后续为最近评估窗口值，结合 `evaluation_id` 判断更新。runner仍可能对一个rollout的多个reset取均值，过渡点可混合两窗口；重复日志点不是新增独立回合。`expanded`为当前reset扩速脉冲，generation才是累计阶段。原逐回合mean ratio与总距离之比区分命名，不能把负effective ratio直接当倒走。

## 基线、兼容性与尚未验证的条件

恢复上一版248573的主要算法设置：

```python
cfg = RobotStairsEnvCfg(
    walking_tracking_mode="command_relative",
    walking_foot_signal_mode="legacy",
    stairs_height_profile="legacy_14cm",
    walking_command_curriculum_mode="global",
)
```

更早版本的mixed地形/height_mode/sole/接触历史开关仍独立保留。没有新增actor/critic输入、动作、网络参数或归一化器；保存模型的结构兼容不等于行为兼容。最终HF统计可能已达到参照实现冻结门槛，不清零或悄悄重建旧normalizer。新课程统计若被重新构造，仍需重新累计。

仍需真实条件日志：同一checkpoint与归一化下，各普通地形、上楼、下楼的有效进度/完成率；逐脚门控开启率、条件净空、接触和滑移；主动进度与inactive残差；实际源码与依赖版本。nearest同次摆动换靶、足底支撑覆盖、固定空中/支撑时长与实际步频、RND因果贡献均未闭环验证。

本轮对训练成功的判断是“修复了可证实的训练条件缺陷，值得在控制变量下验证”，不是“代码与CPU测试已经证明能正常走路”。
