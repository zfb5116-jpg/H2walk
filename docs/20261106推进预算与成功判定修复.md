## 2. 新模式及28项预算

新默认 `budget_v3`，奖励版本 `h2_walk_rewards_v3`。旧 `terrain_v2`、`alternating_v1`、`legacy` 显式保留原版本、奖励字段/参数和配置指纹。新旧模式不能相互恢复。

保留terrain_v2其余21项非零权重，把旧 `walk_signed_progress` 权重设0，再增加7项，共28项。完整旧预算见[11月4日设计表](20261104算法与奖励架构重设计.md)，以下为本次差异：

| 项 | 权重 | 函数输出 |
| --- | ---: | --- |
| `walk_signed_progress` | 0 | 原线性推进退出新模式奖励，原实现供旧模式对照 |
| `budget_walk_advance` | +20 | 本步可支付新进度 / 路线长度 / 控制dt |
| `budget_walk_retreat` | −20 | 实际路线反向位移 / 路线长度 / 控制dt |
| `budget_walk_overspeed` | −0.25 | `[路线前进速度/指令速度−1.2]_+²` |
| `budget_walk_lateral` | −0.25 | `(路线侧向速度/指令速度)²` |
| `budget_walk_yaw` | −0.25 | 根yaw相对固定路线的最短角差平方 |
| `budget_walk_stall` | −0.25 | 最近4秒窗口推进不足或无合格落脚的0/1状态 |
| `budget_walk_success` | +2 | 真实单回合成功事件 / 控制dt，一次性 |

这些权重是待动态验证的实验配置，不能称为已成功训练的配方。奖励管理器仍乘控制dt；成功事件最终一次+2，推进全回合正分最多20。其他事件如交替落脚与落地代价仍沿用各自原有dt积分口径。

## 3. 推进预算如何防止冲刺和反复领分

首个有效物理前样本固定起点p0和指令世界方向d0。当前阶段命令固定，路线长度 `L=walking_forward_speed×episode_length_s`，默认4m；不是世界坐标常数，也不表示完成了整个生成楼梯。每步路线坐标 `s=(p−p0)·d0`，新前沿 `h=max(h_old,clip(s,0,L))`，可支付距离 `g=min(h−h_old,|command|×dt)`。

高水位始终更新为整个已观察的新前沿，被限速截掉或不合资格的部分不保存、不补发。停车不会因指令时间继续增长而领奖；回到旧峰值没有新奖。身体自身yaw改变不旋转路线，指令方向/幅度改变、位置中断或大于5m/s的数据跳变会持续使本回合失效，恢复传感器或再次采样命令不会补预算。

正奖只使用位置差分；物理速度通道用于独立一致性诊断和成功证据。反向代价使用实际反向位移，而非前沿减少。未折扣闭合路线在推进与退回这两个分量上不产生正收益，正推进预算不超过20。

当前PPO gamma=.99，本实现不是 `gamma*Phi(s_next)-Phi(s)` 的策略不变潜势塑形，**不承诺任意闭环的折扣回报为零或非正**。较早取得的分数仍可能比后退扣分折扣更少；需同时看跟踪、超速、偏航和真实终点判定。独立CPU比较包括完整路线，而不是仅看单步奖励。原有0.2m/s目标被4m/s超速压倒的分量反例已反转；这不证明物理轨迹可行或整体策略最优。

新交替事件还要求脚沿固定路线前进至少4cm、身体达到超过已记奖路线前沿至少1cm。被拒绝的事件不能消耗上次获奖脚或进度前沿。防止旋转body方向后，通过左右侧向往返反复领取交替奖。原连续对侧支撑、空中时长、查询有效和落地覆盖等条件继续保留。

## 4. 支撑、落脚与速度诊断

新增 `BudgetWalk/*` 是自然结束回合的诊断，区别于 `Episode_Reward/*` 的按最大回合秒数归一化奖励日志：

| 类别 | 主要字段 |
| --- | --- |
| 路线/预算 | `episode_valid`, `route_progress_ratio`, `progress_paid_fraction`, `route_forward_velocity`, `lateral_velocity`, `yaw_error` |
| 原始接触与地面力 | `raw_contact_fraction`, `force_valid_fraction`, `upward_force_fraction`, `vertical_load_ratio` |
| 几何与支撑 | `geometry_valid_fraction`, `near_surface_fraction`, `coverage_known_fraction`, `coverage_fraction`, `support_valid_fraction`, `support_fraction` |
| 起步与摆动 | `armed_fraction`, `unarmed_air_fraction`, `target_valid_fraction`, `moving_swing_fraction` |
| 速度一致性 | `position_physics_disagreement`, `velocity_diagnostic_valid_fraction` |
| 结果 | `qualified_steps_left/right`, `stable_hold_seconds`, `stall_fraction`, `success` |

`reject_*` 记录落脚不合格原因：周期无效、对侧支撑中断、时间、脚/根推进、未知覆盖、覆盖不足、重复脚、父类推进前沿、固定路线前沿/脚推进和路线无效。这些原因可重叠，不是互斥概率。初始悬空没有启动周期时，结合unarmed_air与armed比例诊断，不能误解为从未抬脚。

连续观测按有限观测时长计算回合均值，再对有观测回合取均值；全未知输出NaN，配套 `*_known_fraction` 区分缺数据和真实零误差。已知/支撑等0/1比例按完整采样时长计算。NaN只表示日志不可用，不能进入奖励或成功判定。新模式退回、偏航等奖励对无效输入保持有限输出且拒绝成功。

足底依旧是5cm GT扫描下的18点几何代理，不能当真实接触面积、CoP、摩擦或碰撞自由证明。遇到覆盖不足应先区分查询未知、脚姿/坐标、过滤地面力和真正悬空，不能直接放宽门槛。

stall以4秒窗口检查新路线前沿是否达到该窗口期望距离的10%，以及是否出现合格交替事件；任一不足置stall成本，持续到下一窗口重评。只有速度但无合格落脚的滑行不能解除步态stall。预算达到上限也不等于已经完成本回合。

## 5. 成功奖金与阶段统计只用一套单回合函数

`StageEvaluator.episode_success_mask` 同时服务奖励阶段和reset前阶段统计。新模式结算顺序为：执行指令捕获→物理转移→奖励共享状态→终止行/普通行的command及traversal tracker各结算一次→共享成功判定→成功奖金→reset前统计/诊断→按行清理。没有提前结束回合；全局 `Stage/passed` 不作为单环境奖金。

原条件全部保留：自然超时且没有同时失败、接近完整20秒、有效前进指令至少2秒、目标至少0.5m、实际有符号/目标距离比0.8–1.2、有效比例至少0.8、数据有效且不出tile、双脚曾合格支撑；上下楼分别还需每脚至少两次新踏面高度记录及最终高度方向正确。

budget_v3额外要求：每脚至少2次合格交替落脚；全回合至少80%的时间存在合格支撑；最终路线进度比0.8–1.2、路线横向偏离≤0.15m；最终连续0.2秒保持当前路线速度/指令比0.8–1.2、yaw差≤0.2rad、投影竖直余弦≥0.9，至少一脚有完整可查询且≥60%近表面覆盖；位置差分与物理速度差≤0.25m/s且有限。允许交替单脚支撑，不要求持续双支撑。成功只是本阶段完成，不命名为20cm全程登顶。

这些新增阈值尚未经真实后端校准。早期timeout、同时failure、丢失支撑、只有位置越线或没有交替不能拿成功奖，也不能混入阶段成功数。每组至少32自然回合、成功率≥80%的窗口验收门槛不变，且只是升级建议；冻结策略的视频和逐足证据仍必需。
