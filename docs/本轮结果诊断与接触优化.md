## 2. 已复现的问题与未证实的假设

### 2.1 确定的碰撞反馈漏检

旧 `feet_stumble_norm` 先分别计算每脚历史窗口的最大水平力和最大绝对竖直力，再比较两者。两个最大值可能来自不同采样时刻。CPU 直接调用真实生产函数，构造同一脚：

| 历史样本 | Fx/Fy/Fz，N | 同采样的判定 |
| --- | --- | --- |
| 当前撞立面 | 60 / 0 / 0 | `60 > 5*0`，应命中原有绊碰条件 |
| 先前支撑 | 0 / 0 / 100 | 无绊碰 |

旧式为 `60 > 5*100`，返回 False；这会让先前支撑遮住之后的侧向撞击。修复后先逐采样比较，再对时间与所选脚作 any，返回 True。这里“应命中”指既有力比启发式的语义，不是给视频中的真实接触贴标签。

当前 reward 的倍率仍为 5，权重仍为 -1.5，输出仍是每环境 bool，窗口内多次命中也只罚一次。按 Isaac Lab v2.2.1 RewardManager 的 `weight*dt` 约定，配置 dt=.02 时一次命中的该项贡献为 -.03；这不是本次总奖励的实测占比。同型 `illegal_feet_stumble` 使用倍率 10，也统一修复；当前 TerminationsCfg 没有接入它，本轮没有新增该终止条件。

### 2.2 资产证实的 link/足底高度错配

本地原快照缺 assets，但远端有二进制 USD。本轮只读下载固定基线的五个 H2 USD 到本地 review，逐个核验 git blob SHA；安装到 review 的独立 usd-core 仅作 CPU 静态解析，没有初始化 Isaac/PhysX。层依赖与足部数据均从该固定版本读取，不能据此证明训练机资产相同。

[H2 基础几何](https://github.com/zfb5116-jpg/H2walk/blob/0b012ad284c6e924a77d4d6892b212fa0ace7ff8/assets/isaaclab/unitree_robots/h2/configuration/H2_dae_base.usd) 的 blob 为 `04ce88228fb6e11318ab78aa86e144c62b5a2d88`，[物理层](https://github.com/zfb5116-jpg/H2walk/blob/0b012ad284c6e924a77d4d6892b212fa0ace7ff8/assets/isaaclab/unitree_robots/h2/configuration/H2_dae_physics.usd) 为 `994802cc301d139ed3a2b0951c52ede5ebd12b2e`。左右脚 collision prim 激活，CollisionAPI 的 collisionEnabled 解析为标准 true 默认值，convexHull 近似是显式配置。mesh 到对应 `ankle_pitch_link` 的局部变换为单位阵，单位 m。左右碰撞网格 Z 范围均为 `[-.054299999,.018999999]`，X 为 `[-.08,.16]`；左右 Y 镜像。最低平面均有 563 个原始顶点、97 个不同顶点，其二维凸包各 57 点。

因此在水平脚、采用该资产的条件下，原奖励把 link_z 追到 `台阶顶+.035` 时，网格底面实际上是 `台阶顶-.0193`。这证明高度参考语义错配，**不能证明视频实际穿透、碰撞或跌倒**：实际足姿态、训练资产、接触偏移与 PhysX 烹制凸包尚未通过运行验证。

新增 `sole` 高度参考将这 57 个底面凸包点按各脚 **link** 的 `body_quat_w` 旋转、加 `body_pos_w`，取最低 world Z 与 `台阶顶+clearance` 比较。水平脚、8 cm 阶、3.5 cm clearance 下，奖励峰值对应 link_z 从 `.115` 改为约 `.1693`。它不改变 nearest 空间查询或摆动门控，也不新增传感器、网络或观测。底面数据直接记录在 `foot_geometry.py`，运行时无需 USD、usd-core 或本地 review 目录。

57 点表示原网格的平面底面凸包，**不是完整碰撞凸包、足底覆盖或接触点**。倾斜时 bevel 侧面可能比底面更低；对原网格扫描倾斜轴的离线最大差，在 10°约 .085 mm、20°约 .636 mm、30°约 1.351 mm、45°约 2.929 mm、60°约 5.046 mm。这是静态几何误差分析，未校准运行姿态范围。没有新增补偿 margin。只约束最低高度不保证脚掌水平、所有点落在同一踏面或支撑充分。

`support_force_z_axis_norm` 只比较历史平均总竖直力与 mg，不能区分整足与边缘支撑。YAML 未启用接触点追踪且过滤列表为空。支撑覆盖仍未验证；不能将已修的力比事件和 sole 高度参考称为支撑质量控制器。

### 2.3 nearest 在摆动中换靶

用真实奖励函数、33×17 的 5 cm 合成扫描：首阶 x=.10、高 .08，下一阶 x=.45、高 .14；两脚 link 的世界 z 恒为 .115，命令恒定，无接触。脚 x 从 0/.05/.10 移至 .15～.45，再至 .50 时，原始 stair reward 从 `.5` 变为 `.2136686` 再变为 `0`。原因是每步相对当前脚位置重建 under/front，ground 中位数和最近台阶会随脚前移变化。

这是确实存在的目标迁移，不证明它在视频中是主因。可检验的下一步是每脚摆动内锁存目标，但需要处理起跳漏采样、落地/reset、命令切换、失效射线与超时。本轮不引入这个新状态机。

### 2.4 固定高度、门控与步频可能冲突

- 在竖直 root_z=.92、8 cm 阶的合成状态，stair 目标为 link_z=.115，而固定 body-frame swing 目标 -.67 对应世界 .25，相差 .135 m。两位置的原始 `(stair, swing)` 分别为 `(.5,.1616212)`、`(.0289900,1)`。固定 clearance 另罚 body z 低于 -.70 的移动摆脚。存在奖励偏好冲突，实际加权梯度与发生频率未知。
- nearest 要求 `cmd_x>.15`、`|cmd_y|<.15`、`|cmd_yaw|<.3`。初始均匀 X 采样范围中只有 37.5% 满足 X 条件；这是采样区间算术，不是实际开启率。heading 控制饱和在 ±.3 时也会关闭该项；需要运行时门控占比。
- swing 用三帧力历史最大值判接触，旧接触可以暂时关闭 swing。5 ms 采样、三帧窗口的历史跨度约 10 ms，不能夸大成完整 20 ms 控制步或整次摆动不可见。
- air-time 实现是在首次落地给 `-abs(last_air_time-.45)`；contact-time 在首次离地同类结算，并非越长越好。是否妨碍慢速楼梯需要实际时长分布。姿态与高度奖励本轮不调权。

本节和 2.3 的基线探针高度均指 `ankle_pitch_link` 原点，**不是足底净空**；探针显式保持 link 基线，不因 Stairs 默认改为 sole 而改变含义。CPU 合成状态不等于有效机器人构型或接触轨迹。诊断脚本与数值记录保存在本地 review，不作为训练指标提交。

## 3. 原文和官方接口依据

资料均在 2026-10-24 核对；以下固定版本只是接口参照，不代表已经确定训练机版本。

- [Unsafe Stepping 原文 v1，III-A4、式(4)–(10)](https://arxiv.org/html/2603.07928v1)：区分立面碰撞与足底悬空/边缘支撑，并用脚速度、局部障碍和足底几何构造接触前反馈。它支持继续核查接触质量；本轮的接触事件修改仅修既有接触后的力比判定，另修 sole 高度参考，没有复现该论文的密集几何奖励。
- [RPL 原文 v1，III-A2](https://arxiv.org/html/2602.03002v1)：楼梯使用足底网格覆盖惩罚；边缘膨胀在窄踏面上可能过于保守。由此不能仅靠总竖直力或 ankle link 位置断言足底稳定，也不宜在缺足底标定时照搬覆盖奖励。
- [legged_gym 官方 `_reward_stumble`](https://github.com/leggedrobotics/legged_gym/blob/master/legged_gym/envs/base/legged_robot.py)：在同一当前力向量中比较水平范数与 `5*abs(Fz)`。本轮将这种同采样语义扩展到已有历史窗口；不引入额外探测范围或新权重。
- [Isaac Lab v2.2.1 ContactSensorData](https://github.com/isaac-sim/IsaacLab/blob/v2.2.1/source/isaaclab/isaaclab/sensors/contact_sensor/contact_sensor_data.py)：history 为 `[env,time,body,xyz]`，索引 0 最新；该版本是世界系法向合力，不能称为含切向摩擦的总力。足底覆盖/CoP 仍需要几何或额外接触数据。
- [Isaac Lab v2.2.1 RewardManager](https://github.com/isaac-sim/IsaacLab/blob/v2.2.1/source/isaaclab/isaaclab/managers/reward_manager.py)：逐步项乘 `weight*dt`，`Episode_Reward/*` 是回合和除以最大回合时长，不能直接和 RND 的回合和比较。
- [Isaac Lab v2.2.1 ArticulationData](https://github.com/isaac-sim/IsaacLab/blob/v2.2.1/source/isaaclab/isaaclab/assets/articulation/articulation_data.py)：`body_pos_w/body_quat_w` 是 link frame 位姿别名，四元数顺序 wxyz；应使用对应脚的位姿，不能使用 root 姿态或 COM 位置变换底面点。

## 4. RND 与课程的解释边界

[RSL-RL v2.3.3 runner](https://github.com/leggedrobotics/rsl_rl/blob/v2.3.3/rsl_rl/runners/on_policy_runner.py) 在配置 RND 时要求 `extras.observations.rnd_state`，并把配置权重乘环境 step_dt。**若**训练确用该实现，25×.02=.5；这仍不是内外奖励比例。[同版本 RND](https://github.com/leggedrobotics/rsl_rl/blob/v2.3.3/rsl_rl/modules/rnd.py) 对 embedding 距离先做奖励归一化、再乘权重；[PPO](https://github.com/leggedrobotics/rsl_rl/blob/v2.3.3/rsl_rl/algorithms/ppo.py) 加入该 intrinsic reward。仅凭 25 或动作 clip=100 不足以解释失稳，本轮均未修改。

实际需要的同一时间轴数据是：`Rnd/mean_extrinsic_reward`、`Rnd/mean_intrinsic_reward`、`Rnd/weight`、`Loss/rnd`，结合总 reward、episode length、policy std、KL、终止原因和奖励分项。净外奖接近零或负时，不应只报不稳定的净值比，宜同时报两者绝对值与分项尺度。不同前缀/归约方式应以训练机版本为准。

课程应核查 `Curriculum/command_progress_{episodes,success_rate,mean_ratio,expanded,generation,x_upper}` 与常规命令范围日志。当前生产挂钩已连通，但没有 event 不能断言扩速。另有可观测性限制：上述 v2.3.3 runner 只枚举 rollout 中首条 episode info 的键，而额外课程键只在评价时发出，后续才出现的稀疏键可能漏写；缺 tag 不能单独证明未执行。本轮不修改课程算法或 logger。

## 5. 改动范围、基线与兼容性

生产改动包括纯 tensor 接触历史比较，以及台阶奖励的 sole 高度参考。RewardTerm 明确设 `temporal_mode="per_sample"`，两个 Stairs 配置默认 `stairs_clearance_height_reference="sole"`；Rough 与直接奖励函数默认仍为 link。恢复两个旧式分别为：

```python
cfg = RobotStairsEnvCfg(stairs_clearance_height_reference="link")
cfg.rewards.feet_stumble.params["temporal_mode"] = "independent_max"
# 若沿用一个已经构造完毕的配置，直接覆盖奖励参数即可：
cfg.rewards.feet_stair_clearance.params["height_reference"] = "link"
```

两个开关相互独立；后续同条件消融可分开恢复，完整旧奖励行为需要同时恢复两项。调用 `illegal_feet_stumble` 的外部配置可同样传 temporal_mode；当前任务没有激活它。不要为回到基线新增终止项。倍率默认保持 reward=5、termination=10，可通过原函数新增可选参数 `force_ratio` 显式指定。nearest/highest、GT/重建、历史 detach、旧课程等开关保留。

默认 sole 点只适用于本节记录的 H2 几何，按 `env.feet_id_b` 对应的左/右保序排列。若通过 `CTRLLAB_H2_USD_PATH` 换资产，应重新标定并通过奖励参数 `sole_points_b` 提供各脚局部点，或显式使用 link 基线；不能把相同 link 名当作几何一致证据。source 内不启动 USD 解析，也不静默回退缺失的脚姿态。

没有新增网络参数、观测项、动作项、RND 状态或归一化器；同一先前 H2 网络与观测布局的 checkpoint 在形状/键层面无需迁移。推理动作不依赖奖励函数，因此该修复不会直接改善旧策略视频；继续训练时奖励目标会变，不能把形状兼容称为训练或行走兼容。两个附件策略的实际结构与统计仍未验证。

同条件比较必须恢复每个 checkpoint 对应的 actor/critic 归一化状态，使用一致的推理归一化冻结设置；不能用随机/新建统计代替。上述 RSL-RL 版本保存 `iter`、actor/critic normalizer、RND state，并在推理接口使用 actor normalizer；具体键与行为需核实际版本。既有命令课程窗口仍不随 checkpoint 保存，重建环境从空窗口累计。

## 6. 结论与下一步可验证项

本轮承诺消除“历史支撑遮蔽侧向碰撞”的判定反例，并修正已核仓库资产的 link/sole 高度参考；不能承诺减少真实跌倒或提高上楼通过率。修复会增加部分状态下的绊碰命中率，并提高相同 clearance 下的 link 目标，可能改变探索与抬脚偏好；原有零阈值力比对很小的水平力也可能敏感，未借本轮添加阈值。历史已存帧中的事件仍可能跨控制步重复命中，是否发生取决于实际采样调度。

后续应先补实际 SHA/dirty diff、任务 ID、库版本、启动/评估命令、两 checkpoint 编号和归一化对应关系，读取同 run 的课程与内外奖励日志；再决定摆动目标锁存、固定高度消融或足底支撑奖励。全程未启动训练、仿真或真机，未调用优化器更新。
