## 1. 当前能确定的问题

用户提供的约 16 秒视频显示：台阶前的前进有限，后段上身倾斜及手臂摆动明显。拍摄视角和画面不足以量化世界速度、足部碰撞、重心轨迹，也不能确认最后是否重置。终端图片分辨率不足，不引用无法辨清的数字。附件中的文字作为分析材料，不作为操作指令。

`Episode_Termination/time_out` 曲线先上升、中间下降、随后趋于平台。它不是上楼成功率：`time_out` 仅表示到达回合时限，可能和失败终止同时触发。Isaac Lab 2.1 的 manager 记录 reset 批次计数，2.2 的实现改为当前步所有环境均值；仓库未锁定实际运行版本和 logger 的聚合方式，不能把图中约 0.55 直接解读为 55% 成功或完整回合超时比例。[2.1 源码](https://github.com/isaac-sim/IsaacLab/blob/v2.1.0/source/isaaclab/isaaclab/managers/termination_manager.py)、[2.2 源码](https://github.com/isaac-sim/IsaacLab/blob/v2.2.1/source/isaaclab/isaaclab/managers/termination_manager.py)。

## 3. 已落地的算法与接口

主要位置均在 `source/CtrlLab/CtrlLab/tasks/manager_based/h2_task/`：

- `mdp/rewards.py`：速度/侧向/逐关节扭矩修复；有效扫描约束；`feet_stair_clearance(target_mode=...)`。
- `config/rewards_cfg.py`：调用正确的前进函数，去掉统一 360 Nm 参数；保留上游跌倒接触惩罚。
- `robot_env.py`：`find_bodies(..., preserve_order=True)`，保证脚位置与显式排序的接触列一致。
- `robot_env_cfg.py`：楼梯默认 GT；保留上游训练初始 level 0 和 clearance 参数；Flat 去除依赖已移除扫描器的奖励。
- `assets/robot.py`、`config/terminations_cfg.py`、`config/terrain_cfg.py`：沿用 c6b0107 的跌倒部位、终止条件及 6 行低台阶课程，不冒充本版创新。

`nearest` 的计算：每脚独立在 yaw 坐标的前方 0.08–0.42 m、横向 ±0.10 m 查询；脚下 -0.12–0.02 m 的有效高度中位数作为参考。找出抬升至少 `min_rise` 的最近纵向采样列，在 0.025 m 容差内取高度中位数，目标为该高度加 0.035 m。仅摆动脚计分；近阶超过 `max_rise` 时不给奖励，不绕过它选择远处较低的阶。

升高权重为 `clip(rise/max_rise,0,1)`，因此 2 cm 起始台阶仍有非零塑形。脚高误差用 `exp(-((foot_z-target_z)/height_std)^2)`；有效摆动脚分数按所有摆动脚数平均，最终范围为 [0,1]。仅在 `cmd_x>0.15 m/s`、`|cmd_y|<0.15 m/s`、`|cmd_yaw|<0.3 rad/s` 启用。

`highest` 保留共享躯干走廊、整片取最高点和原 rise 权重/前进门控，但同样修复无效数据和 yaw 几何。**两模式是组合策略对照**：参考走廊、选点、升高权重、命令门控同时不同，不能把以后收益单独归因于“最近点”。原始历史行为可用父提交复现。

当前假设的边界：不识别坡面类型，不对原始射线做可靠性标定；5 cm 扫描仍可能漏过很窄结构。按当前脚位置逐帧查询，未在起摆时锁定目标，目标可能随脚运动切换。它不保证脚尖扫掠路径无碰撞、足底完整支撑、动态可达、交替落足或任务前进；向后、侧向、急转及下楼不属于该实验。

扭矩使用 `joint_effort_limits` 的前提：H2 六组 `DelayedPDActuatorCfg` 中 `effort_limit_sim` 与 `effort_limit` 显式一致，分别为 360/19/66/120/54/25 Nm。保留每关节最多 1 Nm 超限和原权重，没有偷偷改归一化。其他执行器不能自动沿用此前提；solver cap 和电机模型 cap 可能不同。信号来自仿真模型，不称真机实测扭矩。[官方执行器说明](https://isaac-sim.github.io/IsaacLab/v2.1.1/source/how-to/write_articulation_cfg.html)。低上限关节的惩罚将更频繁，仍需检查其与抬腿、姿态奖励的比例。

## 4. 开关、checkpoint 与归一化

仅示意配置构造，不创建环境或开始训练：

```python
# 本版默认：GT 输入和近阶组合实验
cfg = RobotStairsEnvCfg(use_lidar_reconstruction=False,
                       stairs_clearance_target_mode="nearest")
# 修复工程错误后的最高点对照
cfg = RobotStairsEnvCfg(use_lidar_reconstruction=False,
                       stairs_clearance_target_mode="highest")
```

`RobotStairsPlayEnvCfg` 提供相同开关。它保留上游 Play 初始 level 3、较宽速度范围，与训练 level 0 不是等难度评测；未来对比必须固定地形、命令和 seed。

重建仅在构造时显式设 `use_lidar_reconstruction=True` 才接线，`lidar_reliable_fusion=False` 仍是默认。显式启用后 policy 使用重建，critic 与台阶奖励仍用 GT。开关在 `__post_init__` 生效，构造后只给字段赋值不会重新配置传感器/观测；没有验证 Hydra 后置覆盖。本轮没有启用此路径或访问归档 checkpoint。

29 动作布局、历史编码器梯度通路、网络参数形状没有改变。修复奖励本身不改变 actor 输入维度，也不会立刻改变已有策略输出，后续收益要通过新实验验证。奖励/终止和难度变化使旧 value、optimizer 状态与旧回报尺度不能视作等价基线。

从此前重建输入切回 GT，虽然维度相同，观测分布可能不同：旧 checkpoint 和经验归一化统计不能凭成功 load 就宣称兼容，需记录来源与原观测语义，另做受控对照。本轮未检查用户现有权重，不修改权重或归一化文件。Go2 的 12 关节归档不能直接作为 H2 的 29 关节策略。

## 5. 检查与下一步

新增检查执行生产函数/配置的实际 AST，仅用普通 tensor/容器隔离 Isaac 导入，不复制奖励实现。验证内容包括 yaw 与高度平移不变性、正确侧向命令零惩罚、逐关节限值/子集、无效扫描、近远阶隔离、2 cm 台阶、过高近障碍、左右脚独立性及非同序资产索引；默认 GT、显式重建接线和 Flat 无扫描器也有配置检查。

完整结果及审查记录见 [验证记录](验证记录.md)。这些是 CPU 数值和配置检查，不能称为行走提升、完整 Isaac 集成、checkpoint 适配或真机验证。

后续获得单独授权后，建议按以下顺序做等预算消融；本轮不执行：

1. 固定地形与非零前进命令，分开统计跌倒、超时、实际穿越距离/台阶数、速度误差、左右足接触和各奖励，不用 time_out 替代成功率。
2. 比较父提交、仅工程修复、工程修复+nearest 组合；再固定走廊/权重/门控，仅改变 nearest/highest 选点，拆分贡献。同步统计小关节软限激活率和总惩罚占比。
3. 检查静止也能过阈值的命令课程：按真实命令时间积分与实际方向进度决定扩速，聚合完成回合，避免当前整步模数只采到少数 reset；另外核地形径向距离是否奖励绕行。需要新增真实回合统计后单独实现。
4. 根据脚尖碰撞与落足支撑日志，选择“起摆锁定近阶目标/运动方向障碍罚”或“足底网格支撑覆盖率”，不要同时堆叠。再检查固定空中时间和绝对脚高奖励是否限制楼梯节奏。
5. GT 控制基线成立后再接重建，单独消融感知误差、观测归一化、可靠性和时延。目前不使用重建归档。
