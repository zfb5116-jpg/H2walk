## 新增 event 的诊断与边界

原始 event 为126536855字节，SHA256 `6e15ef871a0dc0be2dc6a36f0398eee85060a531451e45caafe43e6efab55519`，与 LFS 清单匹配。独立审计使用全量读取，不做 reservoir 截断、平滑、去重或 TensorBoard 服务启动：实际有69个 scalar tags，包含63个各30000点的常规项，以及6个各179点的稀疏 progress 项，总计1891074点。学习迭代项覆盖0–29999；两个 `/time` 项的横轴是累计训练秒数，不能当作迭代。文件没有重复/倒退步号、非有限数值或逐tag时间倒退，但不能由单文件排除所有进程重启。

**新 progress 课程实际运行，但没有扩速。** 常规 X 上限在全部30000个迭代保持约 .3 m/s；稀疏 `x_upper` 一致，generation/expanded 均为0。179次可见报告的成功率均值约15.04%、最高19.93%，低于80%门槛。稀疏报告不是全部评估窗口的完整清单，常规 X 上限序列另行支持未扩速结论，因此这次结果不支持“课程扩速造成失稳”。地形平均 level 后期约3.35，来自既有存活/径向位移课程，不能解释为台阶完成率。

progress `mean_ratio` 为负也不能直接称为倒走：源码定义包含“主动 X 阶段有符号进度减去小 X/停令阶段的完整 XY 跟踪残差”，再除以命令距离；日志还包含命令距离低于成功门槛的候选回合。inactive 残差、小分母、反向进度或其混合均可能影响数值，event 没有分别记录这些分量。

| --- | ---: | ---: | ---: | ---: | ---: |
| 10000–19999 | 98.10 | 995.44 | 3.349 | .98381 | 1.25% |
| 25000–29999 | 90.69 | 996.89 | 3.347 | .98917 | 1.46% |
| 29000–29999 | 84.12 | 996.53 | 3.331 | .98845 | 1.66% |

RND实际 weight 始终为 .5，尾1000迭代外在回报均值82.743、内在1.373。它确实贡献了回报，但尾段占比不支持“weight=25所以内在奖励主导”的解释；早期外在回报可能为负，均值比还受抵消影响。没有做RND消融，仍不能排除它对学习行为的影响。

从数据选出的最佳1000迭代窗口16339–17338到尾段，总回报103.47→84.12（约-18.7%），XY/yaw跟踪误差和策略噪声增加；但回合长度996.29→996.53、地形均值3.339→3.331，timeout日志保持高位。结合表中的较宽窗口，可称为后段聚合目标/跟踪表现减弱，不能称为存活崩塌，也不能将两段未对齐视频直接命名为受控的前后退化。timeout是终止日志聚合量，不是上楼成功率。

尾段 `feet_stair_clearance`、`feet_swing_height` 日志均值分别约 .003551、.002260，信号很小；缺少门控开启率和开启条件下的高度误差，不能区分“多数时间未触发”与“触发后目标不匹配”。低 stumble 惩罚也不能排除碰撞，旧独立max归约存在已复现的漏检；现有支撑力日志不测足底支撑覆盖。`Episode_Reward/*` 是加权回合和除以配置20秒后的值，`Train/mean_reward` 与 `Rnd/mean_*` 为回合回报，不能跨单位直接比较。仍缺 KL、逐环境命令/门控、条件净空与足底接触轨迹，以及视频映射。

## 目标和现有问题

应由同一 checkpoint、同一观测布局、相匹配的归一化统计完成平地、轻度粗糙地、缓坡、上楼和下楼。不能拿一个独立 Flat 策略和一个 Stairs 策略的分别表现，替代同一策略的通用能力。

当前 `RobotFlatEnvCfg` 会移除 height scanner 观测，其 actor 输入与包含 561 格扫描的 Stairs 不同。因此本轮保留 `Unitree-H2-Velocity-Stairs` 任务内的 GT 扫描和原 1029 维 actor 布局，在该任务内同时提供普通地形与楼梯。这里的任务 ID 是源码注册项，不是对用户上次实际启动 ID 的追认。

已核实的三个问题：

1. 旧 Stairs 分布有五种上/下楼梯和一种粗糙地，没有明确的平地/缓坡保留；即使最初地形难度低，也不能等同于持续训练普通地形。
2. `feet_swing_height` 追求固定 body-frame z=-.67，`feet_clearance_l2` 惩罚移动摆脚低于 -.70。这些身体高度目标与地面没有直接关系，既可能在普通地形鼓励高抬腿，也可能和局部台阶目标冲突。上轮的真实 CPU 反例已有记录；本轮不据此推断视频失稳的原因。
3. 低速命令下，原固定带宽的速度高斯项对静止也给高分。尾千轮 XY 项为7.587/8，课程有效进度成功率仍低；这不是逐环境因果证明，但与下述 CPU 激励反例相符。

## 1. 保留普通地形训练暴露

新增 `MIXED_WALK_TERRAINS_CFG`，每块仍为 6×6 m、6 行难度，10 列类型。原五种楼梯和 rough_steps 的几何参数保留，新增平地与缓坡：

| 类别 | 列数 | 约占训练环境 | 设置 |
| --- | --- | --- | --- |
| 平地 | 3 | 30% | 坡度范围 (0,0) |
| 缓坡 | 1 | 10% | 坡度系数 (0,.10)，不是 10° |
| 轻度粗糙地 | 1 | 10% | 保留原 rough_steps |
| 上/下楼梯 | 5 | 50% | 保留原五类楼梯，各一列 |

这是待训练验证的初始比例，不是已经优化出的最佳比例。按列分配的整数取整使环境占比只是近似；64、2048、4096 个环境均做 CPU 覆盖检查。

[Isaac Lab v2.2.1 TerrainGenerator](https://github.com/isaac-sim/IsaacLab/blob/v2.2.1/source/isaaclab/isaaclab/terrains/terrain_generator.py) 的 curriculum 生成方式按列位置与累计 proportion 决定类型，不能只看一个连续比例。[TerrainImporter](https://github.com/isaac-sim/IsaacLab/blob/v2.2.1/source/isaaclab/isaaclab/terrains/terrain_importer.py) 近似均分环境到列，运行时升降级只改变难度行，保留列类型。因此普通地形在后续课程行中仍有样本；这证明配置暴露，不证明不会遗忘或已经学会。

两种 Stairs 配置默认 `stairs_mixed_terrain=True`。False 恢复旧六列分布。选用的 generator 和各子配置均复制后使用，避免训练与 Play 互相修改模块级地形对象。

混合 Play 保持 generator.curriculum=True，以生成固定类型列；同时将运行时 `curriculum.terrain_levels` 关闭，使评估期间不升降级。这两个开关作用不同。旧分布 Play 基线仍保留旧的随机 tile 生成方式；在该方式下，不能把 `terrain_types` 列号直接当作真实地形家族。Play 的命令范围与初始 level 仍须显式对齐训练或所选评估条件，本轮没有将它们偷偷改成训练范围。

## 2. 共享抬脚项采用地面相对最低净空

两个现有函数新增 `height_mode="terrain"|"body_legacy"`，直接调用默认保持旧模式；两种 Stairs 配置显式选择 terrain。Rough/Flat 专用任务不自动启用新的扫描依赖。

新模式复用上轮核验的脚底面局部点，以对应脚的世界 link 位姿计算最低 sole 高度。以脚的世界 XY 为中心，在半径 .10 m 内取有限 GT 射线高度的中位数作为局部地面参考。它是局部地面估计，不是精确足底覆盖、斜面拟合或落足规划。缺少有效射线/脚位姿时，该脚项无效；不会以世界 z=0 补一个地面。

对每脚定义：

```text
d = lowest_sole_world_z - local_ground_world_z
u = max(min_clearance - d, 0)
min_clearance = .03 m
```

- `feet_clearance_l2` 使用 `u² × 原脚水平速度因子`，保留摆动和命令门控。
- `feet_swing_height` 使用 `exp(-(u/height_std)²)`，保留原摆动平均与命令门控。

达到 3 cm 最低参考净空后，两个普通抬脚项均进入平台，不再因继续抬至一个固定身体高度而增加收益。较高抬脚仍由关节、力矩等现有代价约束；平台本身不主动惩罚高抬腿。

在所选台阶顶不低于局部地面参考、stairs clearance=.035 m 的条件下，台阶目标处的普通项已经饱和，其高度导数为零，不会把脚从台阶目标往下拉。这一条件通过 CPU 梯度/峰值反例验证，不能扩大为任意地形、射线缺失或所有真实姿态下都无冲突。

新的普通项不看远处的低台阶来降低目标；下楼时参考来自当前脚附近的地面。它没有实现下楼步态规划、摆动目标锁存或足底支撑控制。nearest 台阶项、既有 sole/link 开关、接触历史判定、姿态奖励、固定 .45 s 的空中/支撑时长项均保留，没有同时调权重。

## 3. 低速跟踪按命令幅度设置带宽

[Isaac Lab v2.2.1 官方 XY 项](https://github.com/isaac-sim/IsaacLab/blob/v2.2.1/source/isaaclab/isaaclab/envs/mdp/rewards.py) 使用身体坐标系速度误差与固定 `std=.5 m/s`。命令0.2 m/s、实际静止时，`exp(-(.2/.5)^2)=.852144`，已获得85.2%满分；仅调权重不能改变静止相对正确跟踪的得分比例。

新 `track_command_lin_vel_xy_exp` 保留官方的身体坐标系、XY误差和无接触门控语义，增加 `tracking_mode="absolute"|"command_relative"`。不复用本地另一个带接触门控的同名旧函数。forward 项扩展同样参数，原 `cmd_x>.15` 和小侧向命令门控保持不变。

```text
XY:      sigma = std * max(norm(cmd_xy), .1 m/s)
forward: sigma = std * max(abs(cmd_x), .1 m/s)
reward = exp(-squared_velocity_error / sigma²)
```

Stairs/Play 的 `walking_tracking_mode` 默认选择 `command_relative`；Rough/Flat 和直接函数调用保留 `absolute`。相对模式下 `std=.5` 表示相对带宽，速度下限防止停令时除零。正确跟踪得1，0.2 m/s命令下静止得.018316、实际0.1 m/s得.367879、反向0.2 m/s约得1.13e-7；零命令正确站立仍得1。XY两轴都计误差，侧漂不能替代向前跟踪。

两项权重仍为8/2，满分不变，但总外在回报分布会改变，旧运行末段的RND占比1.66%不能直接外推。窄核可能使远离目标时奖励接近零、降低早期学习信号，楼梯上的速度脉动和噪声也可能影响学习；命令大于1 m/s时相对带宽比原固定带宽更宽。此修改是可证伪的激励形状实验，没有证明更易学习或已经改善行走。

论文原文为取舍提供边界：[Unsafe Stepping，III-A4](https://arxiv.org/html/2603.07928v1)关注接触前碰撞和边缘危险；[RPL，III-A2](https://arxiv.org/html/2602.03002v1)用足底覆盖约束，并指出窄台阶上边缘膨胀可能过于保守。本轮未复现这些几何奖励，也未据低碰撞日志排除支撑瓶颈；相对速度带宽来自本项目日志与CPU反例，不是上述论文的原算法。

## 4. 开关与兼容性

保留本轮之前的训练分布、共享脚高和速度跟踪行为：

```python
cfg = RobotStairsEnvCfg(
    stairs_mixed_terrain=False,
    walking_height_mode="body_legacy",
    walking_tracking_mode="absolute",
)
```

该对照仍保留上轮的 sole 台阶高度参考和同采样碰撞修复；若需更早版本的完整奖励基线，还应按 [上轮诊断](本轮结果诊断与接触优化.md) 分别恢复其开关。地形混合、脚高和跟踪模式可分开切换，便于后续分别消融。

没有新增 actor/critic 输入、动作、网络参数、归一化器、RND 状态或跨步奖励缓存。HF 首末 checkpoint 的参数键/形状已核对为结构兼容，无需因本轮张量形状改版而迁移；仍未加载保存参数或验证推理，不能把结构匹配扩大为观测语义、行为或训练恢复兼容。新的奖励与地形分布需要策略学习，代码替换不会自动让旧权重获得通用行走能力。

继续训练和评估时必须记录各 checkpoint 的原归一化统计及其更新/冻结设置。HF 最终统计 count 已超过 1e8；[RSL-RL v2.3.3 runner](https://github.com/leggedrobotics/rsl_rl/blob/v2.3.3/rsl_rl/runners/on_policy_runner.py) 使用 until=1e8，[normalizer](https://github.com/leggedrobotics/rsl_rl/blob/v2.3.3/rsl_rl/modules/normalizer.py) 在 count 达门槛后不再更新。若实际训练用该实现，直接 resume 会继续冻结统计；不能以为换了地形配置后统计一定会自动重新适应。本轮默认不清空统计、不改更新门槛，保持冻结还是单独设计统计适应实验需显式决定。训练分布改变不允许将新建统计与旧视频直接比较；也不把 Flat 无扫描策略视为可直接互换。默认 sole 几何仍只对应上轮固定 SHA 的 H2 USD，自定义资产必须重新核对或提供足底点。

## 5. 如何判定“普通地形和楼梯都能正常走”

后续需在允许运行训练/评估后，使用同一 checkpoint，固定并记录源码 SHA/dirty diff、资产哈希、库版本、命令、地形 seed/level、推理设置和配套归一化状态，分别汇报：

| 验收类别 | 必须单独查看的结果 |
| --- | --- |
| 平地、缓坡、粗糙地 | 存活、有效命令进度/跟踪误差、侧漂、滑移、碰撞和异常高抬腿 |
| 上楼 | 连续跨越台阶的完成率/层数、撞立面与边缘失稳，不能用站立超时替代 |
| 下楼 | 连续下阶、落脚稳定性、撞击/滑移与跌倒，不能只靠上楼结果代替 |
| 跨类别保持 | 普通地形与楼梯分别达标，不能只报混合平均 reward 或一段精选视频 |

现有命令课程仍按混合回合总体进度扩速，不是各地形家族都通过的门槛；地形课程也仍用存活与径向位移，不能当作上下楼完成检测。本轮没有把这些课程统计改称通用行走验收。nearest 摆动中换靶、固定时长与实际步频的关系、RND 因果消融和新奖励下的占比、足底支撑覆盖仍需运行数据。

全程未启动训练、仿真、真机，没有调用 `optimizer.step()`，没有将 checkpoint 反序列化为模型或执行策略；交接的两份 pkl 没有执行或反序列化。本轮 CPU 检查和独立审查只能验证数值性质、接线与回归，不能替代上述行走验收。
