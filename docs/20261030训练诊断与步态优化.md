## 为什么看起来越训越差

新材料是 [H2walk-isaac-stairs-branch-1029 固定快照](https://huggingface.co/hihikk/H2walk-isaac-stairs-branch-1029/tree/e41c6f180cf7079ec2e2b38d3a949c953acc2deb)，不是旧的 H2walk-branch-30k。新 event 有 110 个 scalar 标签、2,004,640 点；其中 108 个迭代标签精确覆盖 **0–18223**，另两个 time 标签按经过秒数递增，不能作迭代轴。没有重复、倒序或非有限值；`max_iterations=30000` 不能当成实际完成 30k。event SHA256 为 `2e36c00da29a4b8a7ecd3797007412197e0936db8750026ebb22ae76c1a9e760`。

| 总回报 | 0–999：−2.5925 | 14.2533 |
| 平均回合步数 | 0–999：126.240 | 244.601 |

因此，并非所有指标都退化，而是**回报和生存改善，没有同步变成稳定推进和任务成功**。中后段进度聚合指标下降；它们仍不是固定 checkpoint 的受控评估，也不能由此证明每种地形都同样退化。当前瞬时速度核、静态悬脚也得分、无事件可避开固定时长损失等设计，提供了目标错位的具体机制；不能据聚合日志把其中某项认定为唯一因果根源。

上传的实际 YAML 仍是旧混合设置：4096 环境，经验归一化开启、RND 非空、随机 heading ±π、侧向命令、动作延迟、DR、噪声及 push。没有新 Walk 的 stage、过滤接触通道或 bounded 参数，swing 仍没有水平运动门控，nearest 仍逐帧查询。因此，之前新建的固定低速 Bootstrap 与接触诊断没有进入这份配置。HF 没有此 run 的源码包或 commit manifest，不能锁定准确训练 SHA，更不能声称当前新 Walk 已经训练失败或成功。

`base_contact` 末段 logger 均值约 .99198，仍是重要失败线索，但原传感器不区分地面与 self，不能写成“99.2% 真实触地跌倒”。真实接触来源和足底支撑可能仍是主要瓶颈；本轮不屏蔽碰撞、不放宽终止、不改 USD。

还有两处易误读：

- YAML 的 RND weight=25 经参考 RSL-RL runner 的 `weight *= step_dt` 后，event 实际恒为 .5；末段 intrinsic/extrinsic 回报均值比约 **1.9985%**。不支持把 RND 主导当成已证根因，也没有完成 RND 动态消融。[RSL-RL v2.3.3 runner](https://github.com/leggedrobotics/rsl_rl/blob/v2.3.3/rsl_rl/runners/on_policy_runner.py)
- XY/yaw error 日志按固定 12 s 上限累计，未除实际存活时间。回合延长也会使它们升高，不能由 raw metric 升高直接断言真实速度误差恶化；不同滑窗的日志均值也不能相除后冒充严格时长归一化误差。[Isaac Lab v2.2.1 command](https://github.com/isaac-sim/IsaacLab/blob/v2.2.1/source/isaaclab/isaaclab/envs/mdp/commands/velocity_command.py)

新附件视频 19.633 s，采样可见楼梯前屈伸、腾挪和躯干前倾，未见可确认的连续上阶。拍摄画面没有配套位姿、命令、接触或 checkpoint 身份，不能量化净推进或作同条件前后比较。jpg 是已有文字分析的截图，不是原始接触数据；精确数值采用 event。

## 本轮算法范围

新增 Walk 专用 `walking_reward_mode="alternating_v1"`，保留 `legacy` fresh 配置对照。原 Stairs/Rough/Flat 的默认公式、网络、观测、动作尺度和终止不变。改进直接在 RewardManager 计算阶段读取终态，早于 reset 和 command resampling；不是只在 evaluator 增加指标。[Isaac Lab v2.2.1 step 顺序](https://github.com/isaac-sim/IsaacLab/blob/v2.2.1/source/isaaclab/isaaclab/envs/manager_based_rl_env.py)

1. **实际有符号推进。** 使用本步开始捕获的命令和 yaw，将实际 root XY 位移投影到执行命令方向，再除以命令速度与 dt；权重 1。没有正值截断、逐步饱和或支撑门。固定命令、heading、速度下，积分与有符号净位移成正比，等距离前进/退回抵消；反向命令按其方向记分。停止/非有限输入不给分，超过 5 m/s 的单步位移视为无效数据。原速度跟踪继续约束超速；尚未证明组合奖励的动力学最优解。
2. **合格交替落脚。** 用曾观测到的地面支持启动周期，真实离开 raw contact 后进入摆动，合格地面支持才完成落地。要求另一脚持续有效支持、摆动 .08–1.2 s、脚沿命令方向移动至少 4 cm、root 至少净进 1 cm；重复同脚不领奖，同时腾空/原地竖直抬脚不作成功步。新落脚还须超过上次获奖的累计有符号推进纪录，避免重复往复刷同一位置。事件输出除 dt，抵消 RewardManager 再乘 dt；权重 .5。这个纪录不撤回过去单次已发奖励，不宣称整个 gait 项对之后任意退回严格抵消。
3. **有运动的摆脚净空。** 保留原 terrain 净空项及 .75 权重，但新模式要求有效摆动、另一脚支持、脚有沿命令方向的水平运动，过久悬腿停止得分。静态脚抬在 3 cm 不再持续领该项正奖。固定 .45 s 的 air/contact 事件偏差损失权重置零；原有 bounded 时长差项继续保留。
4. **nearest 周期保持。** `nearest_latched` 将末次有效 stance 的世界 Z 候选在 liftoff 锁定，空中前移 6 cm、扫描网格换列不会跳到下一阶。落地、reset 或退出前向门后释放；初始就在空中、抬脚时没有有效候选，不在半空补靶。只在有效运动摆动中给分。它仍是上楼净空塑形，既不是完整落足规划，也没有引入下降目标；平地和下楼继续使用 terrain 净空与交替/推进项。
5. **独立支持代理。** 权重 .25，惩罚 raw 接触却不满足地面支持、或通道无效的比例；复用 filtered upward force、sole/GT 高度与有效性。它不乘到 signed progress 上，避免“有支撑前进、无支撑退回”逃掉负进度。这个代理不测足底覆盖、摩擦裕量、压力中心或可达落点。

共享状态每步只计算一次；部分 reset 清对应环境，异常中止清周期。无效渠道会撤销 stance 资格和当前周期，须重新得到合格支持；不会把扫描缺失当抬脚。状态是环境奖励 bookkeeping，不作为观测，也不随 policy checkpoint 保存。

[FastStair v1](https://arxiv.org/html/2601.10365v1) 的落点/摆动轨迹和分阶段方法支持维护摆动周期目标这一方向；[Gait-Adaptive v1](https://arxiv.org/html/2512.07464v1) 支持区分步态时序与速度任务。两者平台和方法不同，不证明本轮阈值或权重适合 H2；没有照搬其网络、DCM、LoRA 或完整相位控制器。

## 配置与 checkpoint

新 Walk 默认选择 alternating_v1；fresh legacy 对照通过构造 `walking_reward_mode="legacy"`，受审入口对应 `--reward_mode legacy`。时序旧式需另外选择 `walking_cross_time_mode="legacy"` / `--cross_time_mode legacy`。不能构造后只改 flag 作热切换。Train/Play 使用同一档相同奖励模式，后续依旧按六档推进且保留普通地形样本。

协议升至 `h2_walk_fixed_scales_v2`，兼容比较包含 reward mode/version；配置指纹包含完整 resolved rewards、常量参数、支持力阈值及 sole/GT 容差，并保留观测、动作、控制和 wrapper clip 指纹。源内容 hash 继续记录来源；callable 名称和 marker 本身不证明实现真实性或质量。

**v1、无 marker、旧归一化/RND 权重均拒绝自动恢复到 v2**，包括维度相同者。不得丢弃旧统计绕过检查。新实验应从 fresh Bootstrap 开始，同 v2、同配置协议允许阶段迁移；环境证据和奖励状态重新累计。保护仍限受审入口，外部通用 train/play 可绕过。没有修改参数张量键或观测宽度，也没有加载保存权重验证 I/O。

## 证据边界

测试数量和独立审查结果见[验证记录](验证记录.md)本轮条目。CPU 反例检查的是公式、状态生命周期、配置/协议和真实函数接线，**不等于已学会行走**。固定缩放的真实特征分布、PhysX 过滤接触、实际足底支持、自碰、固定 checkpoint 的普通地形/上下楼成功率及 20 cm 能力都未验证。
