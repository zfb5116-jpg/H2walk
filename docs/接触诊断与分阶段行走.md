# 接触来源诊断与保留扫描的分阶段行走

日期：2026-10-29。依据是[上一轮完整训练诊断](20261028训练失败诊断.md)：新 30k run 末段回合约 4.45 s，骨盆接触日志占主导，速度和地形课程未升级。此次实现优先补齐接触证据和低复杂度训练入口，保留原 PPO、网络、奖励及安全终止。没有启动训练、仿真、真机或优化器更新，尚不能宣布实际行走收益。

| `Unitree-H2-Velocity-Stairs-Diagnostic` | 同一基线 MDP，额外启用只读接触来源与 reset 前状态采集 |

阶段任务没有使用原 `Flat`：原 Flat 删除扫描器，不能与扫描策略直接互换。本次保留原 GT 561 点、term-major 五帧历史与 29 动作，预期 actor1029/critic866/RND-state73 布局不变；新诊断传感器不加入 actor/critic。没有创建真实 ObservationManager 复测这些运行时张量。

## 接触来源与终止前状态

新配置为骨盆、左右脚设置四个独立单 body 传感器：`pelvis_ground`、`pelvis_robot`、`left_foot_ground`、`right_foot_ground`。均使用 `.005 s` 物理周期、三帧历史、每 prim 64 的接触数据容量。原全身 `contact_forces` 不变，原 `pelvis >1 N` 等终止也不变。

这里按真实官方接口修正了两类配置陷阱：

- 生成器碰撞对象是 `terrain.prim_path + /terrain/mesh`，父 Xform 不是碰撞对象。当前只支持已经核对的 generator 导入协议；plane/USD 需要另核碰撞路径，启用时拒绝套用同一规则。[TerrainImporter v2.2.1](https://github.com/isaac-sim/IsaacLab/blob/v2.2.1/source/isaaclab/isaaclab/terrains/terrain_importer.py#L202-L226)、[建网格接口](https://github.com/isaac-sim/IsaacLab/blob/v2.2.1/source/isaaclab/isaaclab/terrains/utils.py#L55-L95)。
- 每个 self filter 明确选择一种 link 在各环境中的实例，共 22 个已核 H2 碰撞 link，排除 pelvis。一个 `Robot/.*` filter 会匹配 N×B 个 body，不满足每项与 N 个主传感器对应的要求；单静态地面 prim 是官方例外。[PhysX 107.3 接口](https://docs.omniverse.nvidia.com/kit/docs/omni_physics/107.3/extensions/runtime/source/omni.physics.tensors/docs/api/python.html#omni.physics.tensors.impl.api.SimulationView.create_rigid_contact_view)。

该 link 列表和 sole 几何对应仓库已核 H2 USD。替换资产须重核命名、碰撞体与足底，不能只改文件路径就宣称诊断兼容。运行层检查单 body 名称、更新周期、历史长度、filter 数与 force-matrix 维度；不支持的后端会明确报错。

`classify_pelvis_contact` 只把**同一历史样本**中的过滤力与原净力触发关联，不使用 `net-ground` 残差猜 self。每个 link 分开取力，避免先将相反向量相加而遗漏已观测来源。代码区分：

| `source_code` | 含义 |
| ---: | --- |
| -1 | 缺失或非有限通道，无法归因 |
| 0 | 原骨盆净力未触发；不等于没有碰撞 |
| 1 / 2 | 净力触发样本中观测到 ground / self |
| 3 | 触发窗口中两类均出现；另用 `both_same_sample` 判断是否同刻 |
| 4 | 至少有一帧净力触发无法由有效过滤通道解释 |

这些是来源观测，不是排他的物理因果证明，也不是完整接触点或支撑面积重建。多个接触同属一个 link 时仍是该 filter 的合力。

在 `RobotEnv._reset_idx` 的父类 teleport/reset **之前**结算末步并采集；父类重建 `extras["log"]` 后再合并诊断，避免丢失。初始化、手动 reset 和没有已执行终止 transition 的 reset 不提供自然回合样本。

普通 RSL 标量日志可见 `ContactDiagnostics/` 下的累计自然回合数、有效来源数、净力触发数、ground/self 同刻观测数、无法归因和无效来源数。它们是累计计数，不应把 runner 平均后的数值直接叫独立重建的逐回合概率。详细 `extras["walking_diagnostics"]` 默认最多采集本次 reset 批次的 8 个环境，包含：

- step/env ID、回合秒数、地形列/行、关节名顺序；
- 骨盆高度/倾角/局部距地、q/dq/力矩、raw action 与处理后的关节目标；
- 过滤接触历史、self filter 路径、来源标记、逐脚地面支撑证据及有效性。

详细张量是独立 detached 副本，下一步清除旧样本；不持有完整训练轨迹，不在环境内自行写文件。默认 RSL 标量 logger 不会自动保存这份详细字典，若后续需要逐帧复盘，应由运行端 recorder 保存该字段；仅 event 仍能看到累计来源计数。

[官方 TerminationManager](https://github.com/isaac-sim/IsaacLab/blob/v2.2.1/source/isaaclab/isaaclab/managers/termination_manager.py#L134-L169) 的 `get_term` 在该版本仅保留最后匹配项，不能用于推断共同触发。因此 snapshot 分开保存 `reported_term_flags` 和 `recomputed_predicate_flags`。后者仅对已经核过的原 H2 纯函数，在相同 reset 前状态、原 params 下做诊断性重算；未知或 stateful callable 不会被再次执行，并列入 `predicates_not_recomputed`。这不是对原 compute 的拦截，也不改变原终止 union 或顺序。

## 平地基础协议与独立开关

新 `Walk-*` 配置使用固定 `.2 m/s` 前向、零侧向/转向，关闭 heading command，reset yaw=0、XY±.1 m。所有档位 tile 为 10×10 m，20 s 的预期行程约 4 m，配置校验拒绝预期跨块的速度/时长。运行层另检查真实位置仍在原 tile 内；侧漂进入邻块后，本回合证据永久失效，但不新增终止或修改奖励。

Bootstrap 只有平地；后续各档固定 10 列：6 平地、2 上楼、2 下楼。只保留 generator 的按列类型分配，关闭旧的运行时地形升行与命令扩速项。从中心向外行走时，inverted pyramid 是上楼，regular pyramid 是下楼，命名按真实方向处理。[官方楼梯生成函数](https://github.com/isaac-sim/IsaacLab/blob/v2.2.1/source/isaaclab/isaaclab/terrains/trimesh/mesh_terrains.py#L45)。

以下开关只改变新 profile，默认均为 False，恢复时各自保留 fresh 基线参数：

| 字段 | 开启后保留的基线部分 |
| --- | --- |
| `walking_enable_push` | 原 push 事件 |
| `walking_enable_domain_randomization` | 材料、PD gains/motor strength 随机化 |
| `walking_enable_observation_noise` | 原 policy 观测噪声 |
| `walking_enable_actuator_delay` | 原六组执行器延迟 |

不锁上肢，不改变动作尺度、PD gains/effort 上限、奖励权重和安全终止。简化协议是可证伪实验，不说明其中某个原配置已被证实是失败根因。

开关必须在**新配置构造时**传入，例如 `RobotWalkBootstrapEnvCfg(walking_enable_push=True)`，或使用显式子类默认字段。配置创建后，单独改一个 flag 不会把已置 None 的事件恢复。`validate_walking_profile` 在父环境构造前核对阶段、真实地形、命令与事件等已落地设置，拒绝 flag 与配置不一致的 post-init 覆盖；不静默重做配置。显式阶段 ID 避免了阶段选择歧义。

该校验不是通用配置验证器。四个 ContactSensor 的过滤目标由配置工厂生成，不支持构造后任意重定向传感器路径；运行时的 body/history/filter 数检查也不能证明被手工换过的目标仍是原地面。自定义 USD、地面或 sensor 目标需要重新核对接口与路径，不能只改一个相同长度的 filter 列表后沿用本轮证明。

## 阶段证据门槛

`StairTraversalTracker` 接入与 command tracker 相同的 step/reset 路径。只认当前样本中的正 Z 地面过滤支撑力、有效 GT 局部地面和接近该地面的 H2 sole；水平撞台阶立面不能当支撑。Walk 档位默认 sole/GT 容差 .015 m，小于最低 2 cm 阶差。过滤力、几何或扫描非有限时，保守失效；没有用世界高度零补地面。

每脚分别记录新支持高度纪录与末次净变化。来回踩同两级、只有一只脚成功、单次大跳或最后退回原高度，都不能提供“两级上下阶”证据。这仍是支持高度与跨级证据，不测足底覆盖率，不代表完整落足质量或九级楼梯全部完成。

`StageEvaluator` 默认每个必需 family 至少 32 个自然回合，每 1000 控制步（20 s）可评估；各 family 成功率都达到 .8 才提出下一档。成功回合须同时满足：

1. timeout 且无 failure，存活达到配置时长的 98%；
2. 实际 X 有效暴露≥2 s、目标距离≥.5 m，主动进度比在 [.8,1.2]，扣除 inactive 残差后的比值≥.8；
3. 证据有效、未离开分配 tile、两脚均有地面支持；
4. 对 up/down，两脚各≥2 次相应方向的新支持高度纪录，末次净高度变化也达标。

短回合、无实际推进、非有限数据与缺支撑自然回合保留在对应失败分母；手动/初始 reset、重复消费和旧 generation 不贡献成绩。flat 不能补偿上/下楼失败。

`Stage/` 日志输出当前档、evaluation ID、每 family 样本与成功率、`passed` 和 `next_index`。**它只建议下一档，不在运行中替换 mesh，不启动下一次训练。**训练中的滚动窗口也不等价固定 checkpoint 验收；后续切档前应在配套 `-Play` 中用同一 checkpoint、固定 seed/命令与原档位分别评估普通地形、上楼、下楼，并复核旧档没有退化。

窗口与 tracker 是环境 bookkeeping，不随 policy checkpoint 保存；重建或恢复环境后从空窗口累计，`Stage/window_checkpointed=0` 明示这一点。结果重复显示时用 evaluation ID 区分新评估。

## Checkpoint 与归一化协议

`Walk-*` 使用专属 `H2WalkPPORunnerCfg`：原网络与 PPO 参数保留，RND=None、`empirical_normalization=False`。观测使用原 ObsTerm 固定缩放，避免平地统计先冻结、进入楼梯后却不再适应的隐性分布问题。配置不删除 RND-state 观测，布局保持一致。

这是**新实验协议，Bootstrap 必须从零开始**。旧 12ee 等 normalized checkpoint 虽然网络键/形状相同，输入变换不同，不能直接 resume 这个 fixed-scale 协议，更不能只丢弃旧 normalizer。旧 checkpoint 的诊断应使用原基线或 `Stairs-Diagnostic` 及原配套统计。新 Bootstrap 之后的同协议阶段可继承同一策略/优化器；仍应记录阶段、源码 SHA、checkpoint iteration 和 runner 配置，不声称环境窗口也恢复了。

旧 `H2RoughPPORunnerCfg` 的经验归一化与 RND 保留，故仍可做原协议对照。旧经验统计冻结行为的依据为 [RSL-RL v2.3.3 runner](https://github.com/leggedrobotics/rsl_rl/blob/v2.3.3/rsl_rl/runners/on_policy_runner.py)；本次没有修改或加载任何保存统计，也没有创建真实 runner。

## 检查与边界

新增 CPU 检查覆盖：同刻/异时接触归因、丢失通道、相反力与 NaN；filter 一对一基数和真实网格子路径；实际 RobotEnv reset 前后钩子；真实两个 tracker 和 adapter 串联的正例及水平撞击、NaN、跨 tile 反例；所有档位 Train/Play、旧任务注册、fixed-scale runner 与基线算法对象隔离。

完整数量和独立审查结果见[验证记录](验证记录.md)最新条目。没有进行 PhysX 后端初始化、实际地形生成/训练/策略闭环或真机测试。接口固定参照 Isaac Lab v2.2.1；其他依赖版本和自定义 USD 必须另核。此次实现使问题更可观测，并提供可回退的新训练协议；尚未证明正常行走、上下楼或 20 cm 成功率。
